## 1. 클론 · git 설정 ★ 커밋 전에 반드시

```bash
git clone https://github.com/NulMa/domo-ninja-desu.git
cd domo-ninja-desu
```

### 1.1 author 정보 — **이걸 안 맞추면 나중에 못 고칩니다**

제출물 ⑤(팀원 롤 기술서)가 **커밋 author 와 대조**됩니다. 요강이 그렇게 요구합니다.
그런데 커밋 author 는 **사후 수정이 불가능**하고, 고치려면 history rewrite 라 우리 규약(`09` §4)이 금지합니다.

```bash
git config user.name  "verpivia"
git config user.email "<GitHub noreply 주소>"
```

⚠️ **`--global` 을 쓰지 마세요.** 이 저장소에만 적용합니다(다른 프로젝트 설정을 덮어씁니다).

**noreply 주소 찾는 법** — GitHub → Settings → Emails →
`Keep my email addresses private` 체크 → 바로 아래 `12345678+verpivia-1@users.noreply.github.com` 형태.

> **왜 실제 이메일을 안 쓰나** — 저장소가 public 이라 커밋에 박힌 주소가 영구히 공개됩니다.
> 빼려면 history rewrite 인데 규약이 금지합니다. `nullma` 도 noreply 를 씁니다.

확인:

```bash
git config user.name && git config user.email
```

## 3. AI(Claude Code) 세팅

### 3.1 실행

```bash
cd domo-ninja-desu
claude
```

**`CLAUDE.md` 가 자동으로 로드됩니다.** 프로젝트 규칙·문서 인덱스·현재 진행 상황이 들어 있어
매번 배경을 설명할 필요가 없습니다.

> AI 의 기억(memory)은 **PC 별로 따로**입니다. 저장소에 들어 있지 않으니 그쪽 작업 내역이
> 이쪽에 넘어오거나 하지 않습니다.

### 3.2 Unity MCP 연결 — AI 가 Unity 콘솔·씬을 직접 보게 하는 것

Unity 6 에 **공식 MCP 가 내장**돼 있습니다. 서드파티 설치가 필요 없습니다.

```
1. Unity 실행 (프로젝트 열어둔 상태)
2. Claude Code 에서  /mcp  →  unity-mcp  연결
3. Unity → Project Settings > AI > Unity MCP
4. ★ ▶ Other Connections 를 펼친다        ← 여기서 대부분 실패합니다
5. 대기 중인 연결 요청을 Accept
```

> 🔴 **4번이 핵심입니다.** `Other Connections` 섹션이 **기본으로 접혀 있어서**
> 승인 요청이 안 보입니다. 못 보고 넘기면 그 조합이 **거부 상태로 굳고**,
> 이후에는 승인 창을 띄우지도 않고 자동 거부됩니다. 그때부터는 재시작해도 안 풀립니다.
>
> 이미 그 상태라면: Unity 종료 → `unity/Library/AI.MCP/connections-v2.asset` 삭제 → 재실행 → 다시 승인.
> 상세는 `21_트러블슈팅.md` §1.

**연결 확인 방법** — UI 표시는 믿지 말고 AI 에게 실제로 시켜보세요.

> "Unity 프로젝트 루트 경로 알려줘"

`C:/.../domo-ninja-desu/unity` 가 나오면 진짜로 붙은 겁니다.

⚠️ **`Unity_AssetGeneration_GenerateAsset` 은 쓰지 않습니다** (`D-19` — AI 생성 에셋 배제).
에셋은 Ninja Adventure 팩(CC0)만 씁니다.

### 3.3 (선택) Figma MCP

FigJam 보드를 AI 가 직접 읽게 하려면 공식 remote MCP 를 붙이면 됩니다.
안 붙여도 됩니다 — 필요할 때 PNG 로 내보내도 같은 일을 합니다.

## 4. 작업 규칙 — **CI 가 강제합니다**

규약을 어기면 푸시 후 **빨간불**이 뜹니다. 사람이 지적하는 게 아니라 기계가 막습니다.

### 4.1 커밋 메시지

```
[주체] type(scope): 요약

의도: <왜 이걸 지금 이렇게 했는가>
검증: <무엇을 근거로 통과라고 판정했는가>
```

| 태그 | 언제 |
|---|---|
| `[AI]` | AI 가 만들고 승인만 한 것 — **`검증:` 필수** |
| `[H]` | 직접 썼거나 AI 결과물을 고친 것 |
| `[BAL]` | 시뮬 리포트 근거 밸런스 패치 — `검증:` `지표:` `근거:` 필수 |
| `[REV]` | 되돌림 — `지표:` 필수 |

- **`의도:` 는 모든 커밋 필수**입니다. 무엇을 바꿨는지가 아니라 **왜 그렇게 지시했는지**를 씁니다
- 섞였으면 **`[H]`** 입니다. 사람 판단이 들어간 순간 그 커밋의 성격은 사람 쪽입니다
- **AI 생성분과 직접 수정분은 나눠서 커밋**하세요. AI 가 못 한 게 diff 로 드러나는 게 이 대회에서 가장 값진 증거입니다
- 언어는 한국어 (`type`/`scope` 만 영문)

전체 규약: [`09_커밋_규약.md`](09_커밋_규약.md)

### 4.2 브랜치

평시에는 **`main` 직접 커밋**입니다. 파일 소유권이 안 겹치게 나눠놨습니다(§5).
겹치는 작업이 생기면 짧게 브랜치를 씁니다.

```
<type>/<scope>-<요약>      예)  data/encounters-stage2
                                feat/unity-board-view
```

- **영문 소문자 + 하이픈.** 한글 금지 — CI 에서 경로·캐시 키로 쓰여 깨집니다
- **슬래시는 하나만.** `feat/unity/board` 는 안 됩니다 (git ref 가 디렉토리라 충돌)
- merge 는 `--no-ff`, 끝나면 브랜치 삭제

### 4.3 금지

| | |
|---|---|
| **squash / force push** | 저장소 설정에서도 꺼놨습니다. 히스토리가 심사 대상입니다 |
| **`gh-pages` 브랜치 직접 커밋** | 빌드 산출물 전용. 기계만 씁니다 |
| **에셋 팩 원본 통째 커밋** | 104MB / 2,234 파일. 쓰는 것만 골라 넣습니다 |

### 4.4 푸시 전 (선택, .NET SDK 있을 때)

```bash
dotnet test DomoNinja.sln
```

CI 가 어차피 돌리지만, 미리 보면 빨간불을 안 봅니다. 30초 걸립니다.

## 5. 파일 소유권 — 서로 안 건드립니다

2인이 같은 파일을 만지면 `main` 직선 커밋이 깨집니다. 기능이 아니라 **디렉토리**로 잘랐습니다.

| | 담당 | 소유 |
|---|---|---|
| T1 엔진·파이프라인 | `nullma` | `core/` `core.tests/` `sim/` `tune/` `.github/` |
| **T2 표현·콘텐츠** | **`verpivia`** | **`unity/` · `data/encounters.json` · `assets/`** |

**경계면은 `core/Events/` 이벤트 로그 포맷 하나뿐입니다.**
`core` 는 전투를 계산해서 로그만 뱉고, Unity 는 그 로그를 **재생만** 합니다.
연출이 전투 결과에 영향을 주면 시뮬 결과와 실제 게임 결과가 갈라지고, 밸런스 검증 전체가 무너집니다.
