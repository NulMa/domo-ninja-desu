   본선은 주제가 현장 공개되는 **별개 결과물**이므로 이 게임의 BM은 어디에도 쓰이지 않는다.

2. **"PvE는 밸런스 시뮬의 의미가 절반으로 준다" → 과한 평가였음**
   측정 대상이 "유닛 승률"에서 **"관문을 뚫는 경로가 몇 가지 살아 있는가"** 로 바뀔 뿐이다.
   → 파생: 지표 `M4`(지배 조합 점유율)가 이 구조의 핵심 감시 장치로 승격

3. **"레벨업 자동 증가는 관습을 의도적으로 깬 것" → 사실 오인**
   장르 표준은 **자동 획득 + 골드 구매 하이브리드**이고, 초안은 유료 가속만 뺀 것이었다.
   → 유료 경험치 복원. 근거는 재미가 아니라 **"결정이 없으면 시뮬이 탐색할 전략 축도 없다"**
   → 파생: 지표 `M6`(Lv5 도달 라운드 분포) 신설 — 넣은 기능이 실제로 작동하는지 측정

**빌드 공간 160 → 2,400.** 보조 스킬 C(6,2)=15가 곱해졌지만 **전수 탐색은 지켰다.**

### 밸런스 최적화 방법론 조사 → `17_최적화_방법론.md`

`13` §1.3이 2층 구조까지만 잡고 **"좌표 하강이면 충분"** 에서 멈춰 있었다. 그 앞뒤 다섯 칸이 비어 있었다 —
목적함수 / 예산 배분 / 노이즈 판별 / 탐색 대상 선정 / **`M4`의 정의**.

| 채택 | 내용 |
|---|---|
| **공통 난수(CRN)** | 세트 비교 시 같은 시드. 분산은 √n로만 주는데 **CRN은 그 4배를 공짜로 준다.** 스트림 용도별 분리 필요 |
| **만족도 함수 기하평균** | `M1`~`M7`이 전부 구간 목표 → Derringer–Suich. **기하평균이라 하나만 0이어도 전체 0** |
| **축차 반감법(SH)** | 저시드로 넓게 → 상위만 고시드. 614만 런 → **106만 런** |
| **Morris 스크리닝** | 어느 파라미터를 탐색할지 측정으로 정한다. Sobol은 `N(P+2)`라 예산 초과 |
| **`M4` → `M4a`/`M4b` 분할** | ★ 아래 |
| 처리량 | 이벤트 로그 off / 런 단위 병렬(결정론 유지됨) / 생명 0 조기 종료 |

**가장 큰 발견: `M4`를 무엇으로 재는지가 정해져 있지 않았다.**
평균 클리어율로 줄 세우면 **쉬운 관문만 잘 깨는 빌드가 과대평가**된다.
→ 「빌드 × 관문」 승률 행렬을 만들면 2인 게임 꼴이 되어 메타게임 평가 문헌(α-Rank, Nash averaging)의 도구가 유효해진다.
**`M4a`(최악 관문 기준 점유율) + `M4b`(비추이성 — 관문마다 정답이 다른 정도)** 로 나눈다.

> **`M4b`가 이 게임의 목표를 정확히 표현한다.** 우리가 원하는 건 "모든 빌드 승률이 같은 것"이 아니라
> **"관문마다 정답이 다른 것"** 이다. 평균 승률 균등화만 목표로 두면 최적화기가
> **모든 빌드가 밋밋하게 비슷해지는** 쪽으로 달려간다 — `13` §1.5가 경고한 "균형은 맞지만 재미없는 해".
> 디렉팅 층의 기각에 의존하지 않고 **지표로 미리 막는다.**

**뒤집은 판단 1건** — `13` §1.3의 "좌표 하강이면 충분"은 절반만 맞았다.
좌표 하강의 약점은 구현이 아니라 **상호작용**이다(축을 하나씩만 움직인다). 그런데 Morris가 상호작용을 찾아낼 것이므로,
**상호작용이 있다고 우리 손으로 증명해놓고 그걸 못 다루는 최적화기를 쓰는 꼴**이 된다.
→ **알고리즘 선택을 Morris 결과에 맡긴다.** 유효 차원 ≤8이면 좌표 하강, 8~20이거나 상호작용이 강하면 CMA-ES.
베이지안 최적화는 저차원·소예산에서 가장 강하다고 일관되게 보고되지만 **C# 생태계에 마땅한 라이브러리가 없어 불채택.**

> ★ **6개 전부 장르 비의존이다.** 오토배틀러에 붙은 게 아니라 "시뮬 가능한 게임이면 무엇에든" 붙는다.
> `05` §1.6이 요구한 "파이프라인을 장르에 용접하지 말 것"을 이 문서가 실제로 만족시킨다.
> **본선에서 다른 장르가 나와도 이 6개는 그대로 들고 간다.**

### 첫 커밋 직전 — 브랜치 네이밍 컨벤션 신설 (`09` §5)

사용자 지적: *"브랜치 이름도 일관성 있으면 좋으니 네이밍컨벤션도 문서 남겨두는 게 맞아보임."*

> ★ **타이밍이 맞았다. 첫 커밋 후에 정했으면 이미 만든 이름을 못 고친다** — 브랜치 이름은 merge 커밋에 박히고 §4가 history rewrite를 금지하기 때문이다.

`<type>/<scope>-<요약>` — **커밋 §1.2의 어휘를 그대로 재사용하고 새 단어를 만들지 않았다.**

| 판단 | 근거 |
|---|---|
| **주체 태그(`[AI]`/`[H]`)를 브랜치 이름에 안 넣는다** | ★ §3이 *"AI 생성분과 사람 수정분은 반드시 분리 커밋"* 을 요구하므로 **정상적인 브랜치엔 둘이 섞여 있는 게 맞다.** 넣으면 원칙과 정면 충돌 — **주체는 커밋의 속성이지 브랜치의 속성이 아니다** |

| **영문 소문자 고정** | 커밋 메시지는 한국어인데 브랜치만 영문인 이유 — `github.ref_name` 이 Actions에서 **경로·캐시 키**로 쓰인다. 표현이 아니라 식별자다 |

| **`submission` 태그** | 마감 후 커밋이 하나라도 생기면 **심사자가 어디까지가 제출물인지 알 수 없다.** 기준점이 저장소 안에 있어야 한다 |


> **고치지 않고 허용 오차로 뒀다.** 서든데스 지속이 ~14초라 7% 이고, 방향이
> *"체력이 클수록 조금 빨리"* 라 **탱커에게 유리하지 않다** — 스펙의 의도는 상하지 않는다.
> 0 으로 만들려면 유닛마다 잔여 피해 누적 상태를 들어야 하는데, **7% 를 없애려고
> 결정론 상태를 늘리는 건 남는 장사가 아니다.** 대신 테스트가 "편차 1초 이내"를 감시한다.

#### ★ `skillPower` 의 의미를 데이터가 결정했다

보조 스킬이 「선택한 메인 스킬」을 강화하는 우회로인데, **메인의 대가까지 함께 키우는가**가 안 정해져 있었다.

처음엔 **전부 키우는 쪽**이 단순하고, *"위력을 키우면 대가도 커진다"* 가 배타 선택의 극단화와도
맞는다고 봤다. 그런데 데이터를 보니 `skillPower` 가 **`0.85`·`0.9` 로도 쓰인다** — 보조의 **대가**로.

> `C2-P2` 금강: 받는 피해 −22% 를 **얻고** `skillPower` −10% 를 **낸다**
>
> → 대가까지 함께 줄이면 **`skillPower` 0.9 가 메인의 페널티를 덜어주는 이득이 된다.**
> **대가로 적어둔 값이 부분적으로 버프가 되는 것이다.** 부호가 뒤집힌다.

**규칙을 내가 고른 게 아니라 데이터가 결정했다.** → 이득 방향의 증감분에만 곱한다.

이득/대가를 부호로만 판단하면 `attackInterval`·`moveInterval`·`damageTaken` 에서 **정반대로 읽는다**
(낮을수록 좋다, `_schema` §2). `StatKeys.HigherIsBetter` 한 줄이 그 구분을 맡는다.

| | |

#### 데이터 문제 1건 — `C2-B` 파동

```
데이터: aoe 가 최상위 → 평타마다 전체 광역 (C2 공격 간격 18틱 = 0.9초)
텍스트: "3초마다 최대 체력 12%의 전체 광역 공격"
```

**`every_n_tick` 60 에는 자해만 묶여 있고 광역은 밖에 있다.** 텍스트대로면 광역도 안에 들어가야 한다.

> 수치로 보면 심각하다 — `C2` 최대체력 180 × 12% = **21 피해를 전 적에게 0.9초마다**.
> 3라운드 적 5체 기준 초당 100 이 넘고, 적 체력은 40~75 다.
> **이득은 3.3배 자주 나오는데 대가(자해)는 3초에 한 번**이라 둘이 분리돼 있다.
>
> **저작 실수로 보이지만 고치지 않았다.** 데이터가 정본이고 구조 수정은 저작 판단이다.
> 밸런스 루프가 `M3b` 로 잡겠지만, 그건 한 사이클을 쓰는 것이라 여기 먼저 적어둔다.

#### `dot_ramping` 수치 해석은 확정이 아니다

`baseValue 6 / rampPerTick 0.4 / duration 200` 에서 **「매 초 적용, 피해 = base + ramp × 경과틱」** 으로 읽었다.
매 틱 적용으로 읽으면 20배라 확실히 과하고, 이쪽도 10초 누적 약 460 이라 적 체력에 비하면 크다.
**둘 중 덜 나간 쪽을 택했다. 값의 문제지 구조의 문제가 아니므로 밸런스 루프가 조정한다.**
