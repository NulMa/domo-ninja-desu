## 2. 각자 맡아 구현한 영역

### 2.1 정우태

대회 요강을 먼저 분석해 개발 순서와 AI 활용 방식을 설계했다.

**프로젝트 설계 및 AI 활용 파이프라인**

- 요강 역산 방식으로 개발 순서 확립 — 게임 아이디어보다 제출 요구사항을 먼저 분석
- 프로젝트 범위 결정 — BM/수익화 제외, 난이도 단일화, 저장소 공개 등
- 커밋 규약 수립 — 주체 태그, 의도/검증 필드 필수, squash·force push 금지
- AI 활용 경계 설정 — 수치 최적화·목적함수 정의는 AI에 위임하지 않음, 전투 엔진에 Unity 참조 금지를 CI로 강제
- AI 산출물 검증 및 판정 — 예: AI가 구현한 밸런스 지표 정의를 실측 데이터 근거로 재정의, 잘못 등록된 밸런스 목표치를 스스로 발견해 정정

**전투 엔진(`core/`)**

- 결정론 기반 3종 + 회귀 테스트 구현(부동소수점 금지, 순회 순서 고정 등)
- 전투 코어 구현 — 합연산, 상태이상, 피해/보호막, 타겟팅, 틱 루프, 스킬 해석
- 죽은 유닛이 전투 보드 칸을 계속 점유하는 버그 발견·수정
- 전투 불변식 자동 검사 도입(게이트 4) — "무엇이 항상 참이어야 하는가"를 코드로 명시해 전 시뮬레이션에 상시 적용
- 테스트 376개 작성(core 337 · sim 39)

**시뮬레이터 & 밸런스 자동화(`sim/`, `tune/`)**

- 헤드리스 시뮬레이터 구현 — 4,320가지 캐릭터 빌드 조합을 21,600회 시뮬레이션해 전수 검증
- 밸런스 지표(M1~M7) 및 목적함수 첫 실측
- 밸런스 자동 탐색 루프 구현 — Morris 민감도 분석으로 탐색 대상 선별 후 Optuna(CMA-ES·ASHA)로 최적화
- 밸런스 지표 재정의 — 지배 빌드 점유율 지표를 실측 데이터 근거로 재정의, 런 소요시간 목표치의 산정 오류를 스스로 발견해 정정
- 스테이지별 클리어율 실측 — 스테이지 1·2를 나눠 측정해 스테이지 2 목표 미달을 발견(평균으로는 가려져 있던 문제)

**CI/배포 파이프라인**

- CI 워크플로 구축 — 경계 검사(core의 Unity 참조 금지 등), 커밋 규약 검증, 결정론 회귀 테스트, 야간 밸런스 자동 실행
- 웹 빌드 배포 파이프라인(GitHub Pages) 구축 및 배포 검증 — 배포본을 로컬 빌드와 파일 단위로 대조

**Unity 화면 구현 및 연출**

콘텐츠·규칙 확정 이후에는 Unity 시각 작업에도 직접 참여했다.

- 전투 보드 렌더링·재생 시스템 최초 구현(`BoardView`, `BattleReplayer`) — 봇이 빌드를 골라 런 전체를 자동 재생하는 관전 전용 프로토타입. 실제 플레이어 조작 UI가 만들어지기 전, 시뮬레이터 결과가 화면에 정확히 재생되는지 먼저 검증하는 용도로 구현. 이후 차영록이 이 컴포넌트를 재사용해 플레이어 조작 기반 전투 화면으로 대체
- 픽셀 아트 UI 테마 도입 및 전체 화면 레이아웃 재설계
- 팝업 화면 간 표시 순서(정렬) 문제 정리, 좁은 창 크기 대응
- BGM/SFX 재생 기틀 구축
- 전장 타일맵 편집기 구현 — 스테이지·보스별 전장을 팔레트로 직접 칠할 수 있도록 함
- 무기 시스템 전투 연출 추가 — 무기 갈래별 투사체·근접 공격 모션, 타격 시 히트스톱, 사망 연출, 서든데스 이펙트, 스킬 시전 이펙트
- 정보 화면 구현 — 스테이지 인트로(적 편성 표시), 유닛 호버 시 스펙 표시, 상점 출전 인원 정보 표시
- 팀원과의 작업물 병합 시 씬 파일 충돌 해결(`UnityYAMLMerge` 활용)

**운영 측정 설계**

- 방문자 분석 도구(Google Analytics) 검토 후 기각 — 심사 대상(개발자)의 네트워크 차단 목록에 포함될 가능성을 근거로 자체 엔드포인트(Cloudflare Worker + D1) 방식으로 설계 전환

### 2.2 차영록

기획 뼈대와 타사 유사 장르 게임 분석(방법론만 활용, 분석 결과는 비공개)을 바탕으로 게임 기초 설계를 잡았다.

**게임 규칙 설계**

- 핵심 메커닉 "스킬 노선 배타 선택" 제시 — 캐릭터마다 스킬 2개 중 하나를 사면 나머지는 그 판 동안 사라짐. 이 규칙으로 빌드 조합이 유한해져(4,320가지) 밸런스를 전수 탐색으로 검증 가능해짐
- 전투 규칙 10건 확정(이동 방식·시간 단위·거리 계산·종료 조건·라운드 간 체력 처리 등)
- AI가 제안한 설계안 6건을 게임 완성도 기준으로 뒤집음(예: 적 유닛도 이동하게 함, 정적 배치안 기각)

**Unity UI 구현**

- 화면 인프라 구축 및 10개 화면 배선 — 스테이지 선택, 로스터 선택, 상점, 전투, 결과, 메타 강화 등
- 플레이어 런 상태 관리자(`RunManager`) 설계·구현
- 전투 시스템을 실제 플레이어 흐름에 연결 — 기존 관전 전용 프로토타입을 대체해 `RunManager.PlayRound`를 직접 호출하고 그 결과만 `BoardView`/`BattleReplayer`로 재생하는 `GamePlayController` 구현. 전투 시스템이 실제로 플레이 가능한 형태로 Unity에 나온 지점
- 좌표 배치 UI 구현 — 드래그앤드롭 + 클릭 2단 배치
- 배포판 전용 버그 수정 — 웹 빌드에서 클릭이 전혀 동작하지 않던 문제(EventSystem 누락), 한글 텍스트 전체 미표시(폰트 교체), 팝업이 다른 화면 밑에 깔리던 문제, 캐릭터 스프라이트가 UI를 뚫고 표시되던 문제
- 캐릭터별 전투 연출 구현 — 타격 이펙트, 이동 애니메이션, 승리 연출 등
- 정보 밀도 개선 — 플레이버 텍스트, 캐릭터 정보 팝업 등

**콘텐츠 제작**

- 캐릭터 6종·보스 2종·몬스터 15종 스프라이트 반입
- 스킬·아이템·재화 아이콘 40종 반입 및 데이터 연결
- 스테이지 2 관문 14개 저작(고정 2개 + 변형 12개)

**AI 산출물 검수**

- 무기 판정 로직 정정 — AI는 공격 순간 거리로 무기를 결정했으나, 실제로는 플레이어가 선택한 빌드가 정해야 함을 지적
- 투사체 방향 오류 발견·수정
- 스킬 이름이 매 타격마다 불필요하게 표시되던 문제 발견·수정
- 성장 시스템 관련 AI의 오독 정정 — AI가 "영구 육성이라 범위 밖"으로 판단해 동결했던 기능을 실제 의도(반복 플레이용 소규모 강화)에 맞게 수정
- AI가 지시 범위를 넘어 라운드 패널 구조를 통째로 바꾼 것을 원상복구
- AI가 만들어뒀으나 어디서도 호출되지 않던 전장 프리팹 발견

**제출물 준비**

- 플레이 동영상(제출물 ②) 촬영·편집
- 게임 소개 및 설명 문서(제출물 ③) 작성
- 팀원 롤 기술서(제출물 ⑤) 작성

## 3. 협업 방식

개발 초반에는 작업 영역을 기능이 아니라 디렉토리 단위로 분리했다 — 정우태가 `core/`·`sim/`·`tune/`·`.github/`, 차영록이 `unity/`와 게임 콘텐츠 데이터를 맡았다. 엔진(`core/`)과 화면(`unity/`)이 만나는 지점은 전투 결과를 기록하는 이벤트 로그 포맷 하나로 고정했다. 엔진은 로그를 계산해서 남기고, Unity는 로그를 재생만 한다. 이 경계로 화면 연출이 전투 결과에 영향을 줄 수 없고, 시뮬레이터와 실제 게임 화면이 항상 같은 결과를 낸다.

개발 후반(UI·연출 작업량이 늘어난 시점)에는 두 사람이 함께 `unity/`에서 작업했다. 이때는 기능 단위로 브랜치를 나눠 작업하고, 병합 전 변경 범위가 겹치는지 서로 확인한 뒤 합쳤다. 씬 파일처럼 자동 병합이 어려운 파일은 전용 병합 도구로 다시 병합해 충돌을 정리했다.

의사결정은 배경 설명과 추천안을 정리해 상대에게 전달 → 상대가 확정 또는 수정 → 재확인하는 방식으로 진행했다. 전투 감각이 필요한 결정(적 유닛 이동 여부, 사망 유닛 처리 방식 등)은 AI가 초안을 만들어도 최종 판단은 항상 차영록에게 넘겼다.
