### 이 날의 관통 주제 — **"했다"와 "된다"의 간극**

같은 형태의 실패가 **하루에 네 번** 나왔고 넷 다 **한 단계 더 실행해봤을 때만** 드러났다.

| | 설치·설정은 됐는데 | 실제로는 |
|---|---|---|
| Optuna | `pip install` 성공 | **ask-and-tell 을 돌려보기 전까지** 채택 근거가 증명 안 됨 |
| 게이트 3 | asmdef 4개 생성, 패키지 resolve | **스크립트 0개면 어셈블리가 아예 안 만들어진다** — 참조 여부를 모르는 채 초록불 |
| nullable | `Directory.Build.props` 에 설정 | **Unity 는 그 파일을 안 읽는다** |
| Newtonsoft | Unity 에서 잘 보임 | **dotnet 에서는 없었다** |

> ★ **기술 문서 4장(검증 기준)의 핵심 논지가 여기서 나온다.**
> *"AI 산출물을 어떻게 검증했는가"* 의 답이 **"선언을 읽지 않고 한 단계 더 실행했다"** 이고,
> 그 증거가 위 네 커밋의 `검증:` 줄에 각각 남아 있다.

## 갱신 규칙

- **그 자리에서 적는다.** 마감에 몰아서 고르면 이미 못 찾는다
- 해시는 **push 된 커밋**에서만 고른다 (rebase 로 로컬 해시가 바뀔 수 있다 — `09` §4)
- "잘 만든 커밋"이 아니라 **"판단이 드러난 커밋"** 을 고른다. 실패·되돌림이 오히려 값어치가 크다

### ★ 이날의 패턴 — "넣었는데 안 쓰이고 있었다"

D+2 의 *"했다 ≠ 된다"* 보다 **한 층 안쪽**이다.

| 사례 | 상태 |
|---|---|
| 스킬 3개 | 컴파일 ✅ 단위 테스트 ✅ **전투 루프가 안 부름** |
| 스프라이트 140장 | 파일 ✅ 커밋 ✅ **임포트 타입이 `Sprite` 가 아님** |
| 아이콘 30개 | 데이터 ✅ 파일 ✅ **색인이 명명 규칙 하나만 앎** |
| 배포 로더 | 빌드 ✅ 푸시 ✅ **대소문자가 달라 404** |

> **넷 다 "확인했다"고 말할 근거가 있는 상태였다.** 파일도 코드도 멀쩡히 있고 테스트도 통과한다.
> **쓰는 쪽이 한 번 돌려보기 전까지 아무도 모른다.**
> → `18` 4장에 이 형태를 그대로 쓴다. 검증 기준이 *"선언을 읽지 않는다"* 에서
> **"쓰는 쪽에서 한 번 돌려본다"** 로 한 단계 더 내려간다.
