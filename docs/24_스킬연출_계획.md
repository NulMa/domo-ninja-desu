# 24. 스킬 효과음 · 투사체 연출 계획

> **상태(2026-08-08 D+8 갱신): 절반 들어갔다.** 아래 표 참조.
> 지시(사용자, 2026-08-07): *"각 스킬에 맞는 효과음을 배치하고, 투사체 스킬이라면
> 그것도 날아가도록 하는 게 좋아 보임 — 이건 문서로 기록."*
>
> 이 문서는 **착수 전 설계 메모**로 시작했다. 실제로 넣을 때 이 표를 그대로 쓰면 되고,
> 안 넣기로 해도 *"무엇을 왜 안 넣었는지"* 가 남는다.

| 항목 | 상태 | 어디에 |
|---|---|---|
| §2 선택지 **`B`** (`EventKind.SkillCast` 추가) | ✅ **채택·구현** (D+8) | `23` §2 v1.2 |
| §4 투사체 | ✅ 들어감 — 단 **스킬별이 아니라 무기 갈래별** | `BoardView.WeaponOf` |
| §3 스킬 12종 전용 효과음 | ❌ **안 함** — 무기 갈래 4종으로 갈랐다 | `AudioKeys.Attack*` |
| 스킬 이름 + 테두리 빛 | ✅ 들어감 (계획에 없던 것) | `BoardView.ShowSkillCast` |

> ★ **§3(스킬 12종 소리)을 안 한 이유가 §2 를 판 이유와 같다.**
> `SkillCast` 는 *"누가 액티브를 냈다"* 만 말한다 — **어느 스킬인지는 안 싣는다**(이유는 `23` v1.2).
> 그래서 스킬별 소리를 내려면 이름을 이벤트에 실어야 하는데, 그건 §2 의 `A` 안이고
> 여기서 이미 *"얻는 것에 비해 대가가 크다"* 로 접었다.
> **화면이 스킬 이름을 아는 것**(로스터에서 읽는다)과
> **소리가 스킬을 아는 것**은 같은 문제가 아니다 — 후자는 틱마다 필요하다.

## 1. 지금 소리가 나는 지점

`AudioKeys` 8종이 이미 있고, 전투 중에는 **세 곳**에서만 난다
(`BattleReplayer.Apply`):

| 이벤트 | 소리 | 비고 |
|---|---|---|
| `EventKind.Attack` | `AudioKeys.Attack` | **평타·스킬 구분 없음** |
| `EventKind.Damage` | `AudioKeys.Hit` | 〃 |
| `EventKind.Death` | `AudioKeys.Death` | |

→ **문제는 "소리가 없다"가 아니라 "전부 같은 소리"다.**
스킬 12종이 평타와 똑같이 들리므로, 스킬을 산 보람이 귀에 안 남는다.

## 2. 걸림돌 — 이벤트 로그에 스킬 정보가 없다

`23_이벤트로그_포맷.md` 의 `v1` 은 **동결돼 있다.** 지금 `GameEvent` 에는
*"이 공격이 어느 스킬에서 나왔는가"* 가 없다 — `ActorId` / `TargetId` / `Value` / `Aux` 뿐이다.

그래서 **소리를 스킬별로 가르려면 로그 포맷을 건드려야 한다.**
이건 `H1`(core↔unity 유일한 경계면)을 바꾸는 일이라 가볍지 않다.

### 선택지

| 안 | 방법 | 비용 | 위험 |
|---|---|---|---|
| **A** | `GameEvent` 에 `SourceSkillId`(또는 짧은 enum) 추가 → `v2` | 포맷 변경 · `sim` 재검증 · 게이트 2·3 재확인 | **결정론 회귀 위험.** 로그가 커져 웹 빌드 전송량도 는다 |
| **B** | `EventKind.SkillCast` 를 **새로 추가**하고 기존 이벤트는 그대로 | 추가만 하므로 기존 소비자 안 깨짐 | 이벤트 수 증가(적음). 시전 시점만 알고 *"이 타격이 그 스킬의 것"* 은 여전히 모름 |
| **C** | unity 쪽에서 **추론** — 유닛의 `ActiveSkillId` 와 틱 간격으로 짐작 | core 안 건드림 | ★ **틀린다.** 같은 틱에 평타와 스킬이 겹치면 못 가른다. 추론이 틀려도 아무 데서도 안 드러난다 |

**→ `B` 를 권한다.** 소리·투사체는 *"언제 터졌나"* 만 알면 되고,
그건 시전 이벤트 하나로 충분하다. `A` 는 얻는 것에 비해 동결 포맷을 여는 대가가 크다.

> ⚠️ **`C` 는 하지 말 것.** 이 저장소가 `M7`(타임아웃) 에서 이미 겪은 함정과 같은 모양이다 —
> *"결과 숫자로는 안 드러나는 틀림"* 은 끝까지 안 잡힌다.

1. **평타와 스킬은 반드시 다르게.** 이 작업의 전부다.

   `AudioManager` 에 **같은 키 최소 재생 간격**(예: 60ms)을 두는 편이 안전하다.
3. **상태 부여는 걸릴 때 1회만.** `C5-A` 각인은 도트가 매 틱 도는데 틱마다 울리면 소음이 된다.

## 4. 투사체 — 날아가는 것 4종

팩에 `FX/Projectile/` 이 있다: `Arrow` · `Shuriken` · `Kunai` · `Fireball` ·
`EnergyBall` · `IceSpike` · `BigShuriken` 등.

| 스킬 | 스프라이트 | 비고 |
|---|---|---|
| `C3-B` 표창 | `Shuriken.png` | 회전시키며 날린다 |
| `C4-A` 저격 | `Arrow.png` | 진행 방향으로 회전 고정 |
| `C4-B` 난사 | `Arrow.png` ×3 | 짧은 간격으로 3발, 표적이 다르다(`multi_target`) |
| `C5-B` 연쇄 | `EnergyBall.png` | 대상→대상으로 튄다. 체인이 눈에 보이는 게 이 스킬의 핵심 |

### 구현 지점

`BoardView` 에 이미 **유닛에 안 매인 수명 객체** 선례가 있다 — `HitFx`
(`TickHitFx` 가 프레임을 넘기고 끝나면 스스로 사라진다). 투사체도 같은 모양으로 둔다:

```
ProjectileFx { Transform, SpriteRenderer, Vector3 From, To, float Left, float Total }
TickProjectiles(dt) → 위치 보간, 도착하면 파괴
```

### ★ 놓치면 안 되는 것

> **투사체는 연출이지 규칙이 아니다** (`08` §5.5).
> 화살이 날아가는 **동안에도 피해는 이미 로그에 적혀 있다.**
> 도착을 기다렸다가 `SetHp` 를 부르면 **재생이 전투 진행을 늦추게 되고**,
> 그 순간 `sim` 결과와 게임 결과가 갈라진다.
>
> → **피해 표시는 지금처럼 즉시**, 투사체는 그 위에 얹히는 장식으로만 둔다.
> 비행 시간은 짧게(0.12~0.2초) 잡아 "즉시 맞았는데 화살이 늦게 온다"가 눈에 안 띄게 한다.

## 5. 하지 않기로 한 것

- **스킬마다 전용 이펙트 스프라이트 12종** — 타격 이펙트는 팀원이 이미
  캐릭터 6종 테마별로 갈라놨다(`63bcf9e`). 그 위에 스킬별로 또 나누면
  **화면에서 구분이 안 되는 차이에 에셋만 는다.**
- **보이스** — 팩에 `Voice` 가 있지만 캐릭터 6종 × 스킬 2종이면 12종이고,
  영상 30~60초에 다 안 들어간다. 용량 대비 이득이 없다.

## 6. 착수 순서 — 실제로 어떻게 갔나

1. ✅ `EventKind.SkillCast` 추가 → `23` **v1.2** (`v1.1` 은 `Dodge` 가 이미 썼다)
2. ✅ 게이트 2(`sim` 결정론) · 게이트 4(전투 불변식) · 테스트 376 재확인
3. ❌ 소리 12종 — **안 함.** 무기 갈래 4종(`AttackBlade`/`Blunt`/`Bow`/`Magic`)으로 대체
4. ❌ `AudioManager` 같은 키 최소 재생 간격 — 갈래 4종이라 겹침이 덜해 아직 필요 없다
5. ✅ 투사체 — `HitFx` 와 같은 모양(`WeaponFx`)으로 `BoardView` 에
6. ✅ §4 경고 확인 — 비행 0.16초, 피해는 즉시. `SetHp` 를 늦추지 않는다

### 넣고 나서 알게 된 것 두 가지

> **① 투사체 그림에는 "그려진 방향"이 있다.**
> `Arrow`·`Kunai` 는 ↗ 45° 로 그려져 있어서, 겨눈 각도를 그대로 주면 **항상 45° 들려 날아간다.**
> 파일 크기·이름 어디에도 안 적혀 있어 **그림을 열어보기 전까지 안 드러난다.**
> → `BoardView.StyleOf` 에 그림별 기준 각도를 적었다. (커밋 `efa282d`)
>
> **② `EnergyBall.png` 는 한 장이 아니었다.** 64×16 = 16px 프레임 4장이 이어 붙은 띠인데
> `Single` 로 임포트돼 **구슬 4개가 가로로 늘어선 채** 날아갔다.
> §4 가 "스프라이트 4종"이라고 적을 때 **각각이 한 장이라고 가정한 것**이 틀렸다.

### 그래도 안 하기로 한 것 (§5 에 더한다)

- **스킬별 전용 효과음** — 위 표의 이유. 하려면 `23` 을 `A` 안으로 다시 열어야 한다
- **`C4-B` 난사 3연발 · `C5-B` 연쇄 튕기기** — 로그에 "몇 발"·"어디로 튀었나"가 없다.
  `Damage` 이벤트 여러 건으로 추론할 수는 있지만 그게 §2 의 `C` 안이고, **하지 말라고 적어둔 것**이다
