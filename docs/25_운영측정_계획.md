## 1. 왜 하는가 — 게임을 위해서가 아니다

★ **밸런스에는 못 쓴다.** 심사자 몇 명이 한두 판 하는 게 전부라 표본이 안 된다.
지금 `sim` 은 **21,600런을 1.5초에** 돈다. 사람 데이터가 이길 수 있는 싸움이 아니다.

값이 나가는 건 다른 데 있다:

| | |
|---|---|
| **대회 문맥** | 메인 카피가 *"AI의 다음 단계를 설계할 디렉터"* 다. **운영 루프를 설계했다**는 건 게임 내용보다 상위 신호다 |
| **본선 자산** | 예선에서 본선으로 넘어가는 유일한 자산은 파이프라인이다(`05` §1.6). 측정 루프는 **장르에 안 묶인다** |
| **기술 문서** | *"`sim` 예측 분포 ↔ 실제 사람이 고른 분포"* 를 나란히 놓을 수 있다. **표본이 적어도 루프를 닫았다는 건 보여진다** |

> ⚠️ **문서에 쓸 때 「사람 데이터로 밸런스를 잡았다」고 쓰지 말 것.** 그건 사실이 아니고,
> 표본 수를 물으면 바로 무너진다. **「예측과 실측을 대조하는 자리를 만들었다」** 가 정확한 주장이다.

> 재튜닝 대상에 넣을 것. (S1 40.9% 상단 초과는 이미 알려진 건)

> ⚠️ 스테이지 데이터는 **S1·S2 둘뿐**이다(`encounters.json`·`encountersStage2.json`).
> 3~6은 잠금 아이콘만 달려 있다.

### ★ 이 숫자를 「유저가 고른 것」으로 읽으면 안 된다

`M3a` 는 **빌드 공간을 전부 돌려본 결과**다. 사람이 무엇을 골랐는지가 아니다.

**"S2 는 수도승 없이는 거의 못 깬다"** 로 읽어야 한다.

**바로 이 차이가 §1 에서 말한 대조의 내용이다.**

## 3. 무엇을 보낼 수 있는가 — 게임 쪽은 준비돼 있다

D+8 에 확인했다. **보낼 것이 전부 한자리에 모여 있고 훅 지점은 두 곳뿐이다.**

| 항목 | 출처 |
|---|---|
| 고른 캐릭터 3명 | `RunState.Deployed[].CharacterId` |
| 액티브 2택 | `RosterEntry.ActiveSkillId` |
| 보조 스킬 | `RosterEntry.SupportSkillIds` |
| 아이템 | `RosterEntry.Items` |
| 스테이지 · 라운드 | `RunState.StageId` · `.Round` |
| 클리어 여부 · 이긴 라운드 수 | `RunManager.LastRunCleared` · `.LastRunRoundsWon` |

**훅 지점**
- `RunManager.PlayRoundWithPlacement` 끝 — 라운드 결과
- `RunManager.EndRun` — 런 마감(빌드 + 결과)

→ **전투 로직은 안 건드린다.** core 도 안 건드린다.

## 4. 어디로 보내는가 — GA 를 안 쓰기로 한 이유

GitHub Pages 는 정적 호스팅이라 **서버가 없다.** 받아줄 곳이 하나 필요하다.

### 검토한 것

| 안 | 소요 | 판단 |
|---|---|---|
| **GA4 + gtag.js** (`index.html` 수정 + `.jslib`) | ~1.5h | ❌ 이 프로젝트엔 **커스텀 WebGL 템플릿이 없어서** Unity 가 매 빌드마다 `index.html` 을 새로 만든다 — `Assets/WebGLTemplates/` 부터 만들어야 함 |
| **GA4 Measurement Protocol** (C# 에서 직접 POST) | ~1h | ❌ 템플릿은 안 건드려도 되지만 아래 세 가지가 그대로 걸린다 |
| **Cloudflare Worker + D1** | ~1.5h | ✅ **채택** |

### ★ GA 를 접은 진짜 이유 세 가지

**① 광고 차단기 — 이게 제일 크다.**
`google-analytics.com` 은 모든 차단 목록에 있다. **심사자가 NHN 개발자들이다.**
uBlock Origin 사용률이 일반 사용자와 비교가 안 된다. 안 그래도 적은 표본이 절반 가까이 날아갈 수 있고,
**날아간 것을 알 방법이 없다.** ("데이터가 없다"와 "차단됐다"가 화면상 같다 — 이 저장소가 반복해서 걸린 모양이다.)

**② 커스텀 파라미터를 미리 등록해야 한다.**
GA4 는 이벤트 파라미터를 관리 화면에서 「맞춤 측정기준」으로 등록해야 보고서에 나오고,
**등록 이전 데이터는 소급 적용이 안 된다.** 빠뜨리면 데이터는 쌓이는데 조회가 안 된다.

**③ 표준 보고서 24~48시간 지연.**
실시간 보고서는 30분치 + 파라미터 분해 제한. **마감일 데이터를 문서에 못 넣는다.**

### 그리고 목적에 안 맞는다

GA 는 *"이벤트가 몇 번 일어났다"* 는 잘 알려준다. 우리가 필요한 건
**런 단위 raw 레코드를 `sim` 출력과 조인하는 것**이고, GA4 무료로는 BigQuery 연동까지 가야 한다.
자체 엔드포인트면 SQL 한 줄이고, **`/stats` 를 만들어두면 그 응답을 그대로 문서에 넣을 수 있다.**

> GA 를 굳이 쓴다면 **보조로만** — 세션 수·이탈은 GA 가 편하다.
> **선택 분포는 자체 엔드포인트로 가른다.**

## 5. 설계에서 지켜야 할 것

### ★ 전송은 게임에 절대 영향을 줄 수 없어야 한다

`IEventSink` 를 쓰기 전용으로 둔 것과 **같은 이유**다(`23` §1).

- 응답을 기다리지 않는다. `yield return` 으로 프레임을 막지 않는다
- 실패해도 조용히 넘어간다. 예외를 밖으로 던지지 않는다
- 엔드포인트가 비어 있으면 **로컬에만 쌓고 끝난다** (개발 중 기본값)

> 여기서 한 번이라도 블로킹하면 **네트워크가 느린 심사자의 화면이 멈춘다.**
> 그건 "게임이 구리다"로 읽히지 "서버가 느리다"로 안 읽힌다.

### 개인정보

- **식별 정보를 안 보낸다.** 익명 세션 id(GUID, `PlayerPrefs`)만 붙인다 — 같은 사람의 여러 런을 잇기 위한 것
- 쿠키 없음, 제3자 전송 없음
- 수집 사실을 **화면 어딘가에 한 줄** 적는다(설정 화면 또는 타이틀 하단)
- 수집 항목·목적을 `docs/submit/` 기술 문서에 적는다

### 비용

요강상 **유료 API 비용은 참가자 부담**이다. Cloudflare Workers·D1 **무료 티어 안에서만** 쓴다
(표본이 수백 건 규모라 근처도 안 간다).

## 7. 하지 않기로 한 것

- **실시간 대시보드** — 표본이 수백 건인데 대시보드를 만드는 건 노력 배분이 틀렸다. `/stats` JSON 이면 충분하다
- **A/B 테스트** — 표본이 안 된다. 넣으면 *"통계를 모르는 사람"* 으로 읽힌다
- **플레이 영상·리플레이 업로드** — 이벤트 로그 한 판이 수만 건이다. 무료 티어를 넘고, 얻는 것도 없다
- **밸런스 자동 반영** — 사람 데이터로 `/data` 를 자동으로 고치는 것. 표본이 이걸 감당 못 한다.
  `[BAL]` 커밋은 사람이 넣는다는 규칙(`16` §0.4)이 그대로다
