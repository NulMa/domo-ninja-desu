## 1. 지금 만들고 있는 게임

> **고정 로스터 6명 중 3명을 뽑아, 캐릭터마다 되돌릴 수 없는 스킬 노선을 골라가며 8개의 정해진 관문을 뚫는 3~5분 오토배틀러.**

**이미 확정된 것 (바꾸지 않음)**

| 항목 | 값 |
|---|---|
| 런 구조 | 8라운드 / 생명 3 / 라운드제 PvE (정해진 적) |
| 적 구성 | 라운드마다 미리 만들어둔 변형 2종 중 무작위 |
| 로스터 | 6명 중 **3명 출전** (런 시작 시 1회 선택, 변경 불가) |
| 스킬 | 캐릭터당 2개, 진입 시 둘 다 비활성 |
| **배타 규칙** | 한쪽을 사면 **다른 쪽은 그 런 동안 상점에서 영구 제거** |
| 스킬 강화 | 활성화한 스킬만, 3단계 누적 |
| 상점 | 매 라운드 등장, **4칸 무작위**, 출전 3명의 스킬만 풀에 포함 |
| 재화 | 런 전용(종료 시 소멸). 안 쓰고 넘길 수 있음 |
| 보드 | **2행 × 2열 = 4칸에 3명 배치** (전열 2 / 후열 2) |
| 목표 세션 | **1런 3~5분** |

**플랫폼**: 웹 빌드(Unity → WebGL → GitHub Pages). 데스크톱 브라우저 기준.
**일정**: 제출 8/9. 즉 **구현 기간이 실질 일주일이다.** 판단 시 구현 비용을 크게 잡아야 합니다.

## 2. 왜 전투 규칙에 이상한 제약이 붙는가 — 결정론

이 프로젝트의 차별화 축은 **밸런스를 사람이 감으로 맞추지 않고 시뮬레이션으로 맞춘다**는 데 있습니다.

```
전투 로직(순수 C#) → 렌더링 없이 수만 판 자동 시뮬
  → 유닛/스킬별 통계 리포트 → AI가 데이터 패치 제안 → 재시뮬 → 검증 → 커밋
```

### 2.1 시뮬 규모

빌드 조합이 유한합니다.

- 로스터 6명 중 3명 = **20가지**
- 출전 3명 각각 스킬 2택 = **8가지**
- → **핵심 빌드 160개**

**160개 빌드 × 상점 시드 100회 = 16,000런**을 CI에서 돌립니다.
빌드를 샘플링하는 게 아니라 **전부** 돌리기 때문에 "이 조합이 우세한 것 같다"가 아니라 **"전부 돌려봤더니 최상위 빌드 점유율이 X%"** 라고 말할 수 있습니다.

### 2.2 그래서 결정론이 필수다

**같은 시드 → 항상 같은 결과**가 성립해야 합니다. 안 그러면:

- 밸런스 패치 후 승률이 52%→48%로 변했을 때 **패치 효과인지 노이즈인지 구분이 안 됩니다**
- 노이즈를 줄이려면 판수를 늘려야 하는데, 분산은 √n로만 줄어듭니다 (절반으로 줄이려면 4배)
- 시뮬(순수 C#)과 실제 게임(Unity)의 결과가 같다는 것도 증명할 수 없게 됩니다

### 2.3 코어 작성 규칙 (이미 확정)

전투 로직은 **Unity에 의존하지 않는 순수 C# 라이브러리**로 분리돼 있습니다.

```
/core    순수 C#. UnityEngine 참조 금지    ← 전투 로직은 전부 여기
/sim     콘솔 앱. core를 참조해 대량 시뮬
/unity   core를 참조. 렌더링·입력·UI만 담당
```

| 금지 | 대신 |
|---|---|
| `System.Random` | 시드 주입형 자체 PRNG |
| `Dictionary`/`HashSet` 순회에 결과가 의존 | `List` + 명시적 정렬 |
| `DateTime.Now`, `Guid.NewGuid()` | 외부 상태 주입 금지 |
| 부동소수점 누산 순서 의존 | 가능하면 정수/고정소수점, 안 되면 순서 고정 |
| **실수 델타타임(프레임 기반 진행)** | **고정 틱** |

> **A 트랙의 결정 중 몇 개는 취향이 아니라 이 제약에서 나옵니다.**
> 특히 시간 모델과 타겟팅 동률 처리는 어기는 순간 위 전체가 무너집니다.

## 3. 판단할 때 걸어야 할 저울

| 축 | 왜 |
|---|---|
| **구현 비용** | 실질 일주일. 시스템 하나가 하루를 먹으면 다른 걸 못 만든다 |
| **결정론 유지 비용** | 복잡한 규칙일수록 비결정성이 스며들 틈이 는다 |
| **시뮬 속도** | 16,000런이 CI에서 몇 분 안에 끝나야 밸런스 루프가 돈다 |
| **60초 영상 가독성** | 심사 제출 영상이 30~60초다. 화면에서 무슨 일이 벌어지는지 읽혀야 한다 |
| **3분 온보딩** | 심사자가 직접 플레이한다. 처음 3분에 이해 못 하면 끝이다 |

**"재미있을 것 같다"보다 위 5개를 먼저 봅니다.** 재미는 밸런스 시뮬로 나중에 끌어올릴 수 있지만, 위 5개는 구조라 나중에 못 고칩니다.
