## A-1. 유닛이 이동하는가 ★ 최상위

**질문:** 전투 중 유닛이 보드 위를 움직이는가, 아니면 배치된 자리에 고정인가?

| | 이동 있음 (TFT식) | **이동 없음 (고정)** |
|---|---|---|
| 구현 | 경로 탐색 + 충돌 처리 필요 | 사거리 판정만 |
| 결정론 | 이동 순서·타이브레이크가 전부 비결정성 후보 | 유지 쉬움 |
| 시뮬 속도 | 느림 | 빠름 |
| 2×2 보드에서 | 움직일 공간이 사실상 없음 | — |

**추천: 이동 없음 (고정 배치)**

**근거**
- 2×2 보드에서 이동은 의미가 없습니다. 이동을 살리려면 보드를 키워야 하고, 그러면 3명 배치가 허전해집니다
- 경로 탐색이 들어오는 순간 결정론 유지 비용이 급등합니다 (동시 이동 처리, 칸 점유 경합)
- 구현 시간을 하루 이상 아낍니다

**대가**
"오토체스"보다 정적으로 보입니다. 배치의 의미는 `A-3`(사거리)이 담당하게 됩니다.

## A-2. 시간 모델

**질문:** 전투가 시간을 어떻게 진행시키는가?

**추천: 고정 틱 (20 tick/sec) + 정수 누적**

- 매 틱마다 모든 유닛의 공격 게이지를 정수로 누적, 임계 도달 시 공격
- 렌더링 프레임률과 완전히 무관하게 진행

**근거**
실수 델타타임(프레임 기반)을 쓰면 **PC 성능에 따라 전투 결과가 달라집니다.** 시뮬(콘솔)과 실제 게임(브라우저)의 결과도 갈라집니다. 결정론이 즉시 깨집니다.

> **이건 사실상 협상 불가 항목입니다.** 다만 틱 레이트(20/sec)는 조정 가능합니다 — 높이면 정밀하고 느리며, 낮추면 빠르고 거칩니다.

## A-3. 거리와 사거리 규칙

**질문:** "사거리"를 어떻게 표현하고 거리를 어떻게 재는가?

| | 그리드 좌표 거리 | **전열/후열 2단계** |
|---|---|---|
| 표현 | 유클리드/맨해튼 거리 계산 | `range=1` → 적 전열만 / `range=2` → 적 후열까지 |
| 결정론 | 부동소수점 비교가 끼어들 여지 | 정수 비교뿐 |
| 이해도 | 설명이 필요 | 한 문장 |

**추천: 전열/후열 2단계만**

**근거**
- 2×2 보드에 유클리드 거리는 과합니다
- **배치 결정이 "전열에 둘까 후열에 둘까" 하나로 압축되어 온보딩이 쉬워집니다**
- 60초 영상에서도 "앞줄이 맞고 뒷줄이 쏜다"가 즉시 읽힙니다

**파급**
→ B 트랙의 **로스터 역할 분포**가 여기에 종속됩니다. 전열/후열 개념이 정의돼야 "탱커/원거리"라는 역할이 정의됩니다.

## A-4. 기본 타겟팅 + 동률 처리

**질문:** 유닛은 누구를 때리는가? 후보가 동률이면?

**추천: 가장 가까운 적 (전열 우선). 동률이면 슬롯 인덱스 오름차순.**

**근거**
- 스킬의 `targeting` 효과가 이 기본값을 덮어쓰는 구조로 설계됩니다 (예: 최저 HP 우선, 후열 우선)
- **동률 처리를 명시하지 않으면 리스트 순회 순서에 결과가 의존하게 되고, 그게 곧 비결정성입니다.** 실제로 가장 흔하게 터지는 버그 지점입니다

## A-5. 전투 종료 조건 · 타임아웃

**질문:** 전투는 언제 끝나는가? 서로 못 죽이면?

**추천: 한쪽 전멸 시 종료. 그 전에 45초 경과 시 남은 HP 총합이 높은 쪽 승리.**

**근거**
- 타임아웃이 없으면 **교착 상태에서 무한 루프**가 가능합니다
- 더 중요한 건 **시뮬 실행 시간의 상한**입니다. 16,000런을 CI에서 돌리는데 상한이 없으면 전체 시간이 예측 불가가 됩니다
- 45초는 임시값입니다. 라운드당 20~30초 목표(1런 3~5분)에 맞춰 조정 가능합니다

**논점**
타임아웃 판정을 "HP 총합"으로 할지 "HP 비율 합"으로 할지 — 후자가 탱커 편중을 줄입니다. 의견 주시면 좋겠습니다.

## A-6. 라운드 간 HP · 사망 처리

**질문:** 라운드에서 죽은 유닛과 깎인 HP는 다음 라운드에 어떻게 되는가?

| | 누적 손상 | **매 라운드 완전 회복** |
|---|---|---|
| 긴장감 | 높음 | 낮음 |
| 런 안정성 | 초반 실수가 눈덩이 → 조기 사망 | 매 라운드가 독립 시험 |
| 지표 해석 | 라운드별 패배율이 앞 라운드에 오염됨 | 깨끗 |

**추천: 라운드 종료 시 전원 완전 회복 · 부활**

**근거**
- 3~5분 세션에서 누적 손상은 **런이 너무 일찍 죽게** 만듭니다. 심사자가 게임을 끝까지 못 보면 손해가 큽니다
- 밸런스 지표 중 "라운드별 패배율 분포"로 난이도 곡선을 보는데, 누적이면 이 값이 앞 라운드 상태에 오염되어 **난이도 곡선을 못 읽습니다**
- 생명 3개가 이미 실패 페널티 역할을 합니다

## A-7. 스킬 발동 방식

**질문:** 스킬은 어떻게 발동하는가?

**추천: 전부 패시브 또는 자동 트리거. 플레이어가 발동시키지 않는다.**

- 상시 패시브: `공격력 +20%`
- 조건 트리거: `HP 50% 이하가 되면 ~`
- 주기 트리거: `8초마다 ~` (쿨다운을 이걸로 표현)

**근거**

## A-8. 전투 중 개입 포인트를 둘 것인가

**질문:** 전투가 진행되는 동안 플레이어가 뭔가 할 수 있어야 하는가? (필살기 버튼, 가속 등)

> 참고로 이 안건은 **역기획 자료에서 나온 지적**입니다 —
> *"전투가 실시간 오토라면 오버클럭/게이지 같은 개입 포인트를 최소 1개는 남겨야 '방치형'이 아닌 '전략 게임'으로 체감됨"*

**추천: 넣지 않는다**

**근거**
- 개입이 들어오면 **시뮬과 실제 플레이가 갈라집니다.** 시뮬은 사람이 아니므로, 개입이 승패를 가르는 게임은 시뮬 결과가 실제를 대표하지 못합니다. 이 프로젝트의 차별화 축 전체가 여기 걸려 있습니다
- 개입 지점은 **전투 전에 이미 3개** 있습니다: 무엇을 살까 / 어디에 배치할까 / 지금 살까 아껴둘까

**대가**
"보고만 있는 게임"으로 보일 위험은 실재합니다. → **관전 재미는 연출로 확보**하고, 게임 소개서에 "의사결정은 전투 전에 있다"를 명시하는 방향으로 대응합니다.

**이견이 있다면 이 항목입니다.** 위 지적을 하신 분이 A 트랙을 맡으셨으니, 판단을 듣고 싶습니다.

## A-9. 연출과 로직의 분리 ★

**질문:** 스킬 발동 연출이 전투 진행에 영향을 주는가?

**추천: 절대 주지 않는다. 로직은 틱으로만 진행하고, 연출은 렌더링 레이어에서 따로 재생한다.**

**근거**
연출 때문에 전투가 잠깐 멈추거나 느려지면 **시뮬 결과와 실제 게임 결과가 달라집니다.** 코어를 Unity에서 분리한 이유 자체가 무너집니다.

**구현상 의미**
- 코어는 "3.4초 시점에 C2가 스킬 발동, 대상 E1, 데미지 40" 같은 **이벤트 로그**를 뱉습니다
- Unity는 그 로그를 받아 연출을 재생만 합니다. 연출이 길어도 로직 시간은 그대로입니다

> UI 만들 때 실수하기 딱 좋은 지점이라 미리 못박아 둡니다.
