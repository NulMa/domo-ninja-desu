# 이벤트 로그 포맷 v1 (`H1` 핸드오프)

작성일: 2026-08-02 (D+2)
전제: `08_게임_스펙.md` §5.5, `19_구현계획.md` §2.5 · §4.3
코드: `core/Events/GameEvent.cs` · `core/Events/BattleLog.cs` · `core/Events/DummyBattleLog.cs`

> **이 문서는 T2(Unity) 가 T1(core) 을 기다리지 않게 하려고 있다.**
> `19` §4.1 이 정한 대로 **core 와 unity 의 경계면은 이것 하나뿐이다.**
> 이 포맷만 알면 전투 코어가 아직 없어도 View 를 끝까지 만들 수 있다.

---

## 0. 먼저 알아야 할 것 세 줄

1. **unity 는 core 의 함수를 호출하지 않는다.** `BattleLog` 객체 하나를 받아 **재생만** 한다.
2. **로그에 없는 정보는 화면에 그릴 수 없다.** 필요한 게 없으면 View 에서 계산하지 말고 **T1 에 요청한다** (§6).
3. **v1 은 D+5(`H4` core 안정판)까지 동결한다.** 바꾸면 `BattleLog.FormatVersion` 을 올리고 이 문서 변경 이력에 적고 **즉시 알린다.**

---

## 1. 받는 것 — 타입 2개

```csharp
BattleLog log = ...;          // 전투 1회 = 라운드 1회

log.Version                   // 포맷 버전. 1 이 아니면 이 문서보다 코드가 앞선 것이다
log.Stage                     // 1 or 2
log.Round                     // 1..8
log.Seed                      // 재현용. 버그 제보할 때 이 값을 같이 준다
log.Units                     // IReadOnlyList<UnitSpec> — 전투당 1회, 등장 유닛 전원
log.Events                    // IReadOnlyList<GameEvent> — 시간순
```

### 1.1 `UnitSpec` — 무엇을 그릴지

| 필드 | 의미 |
|---|---|
| `UnitId` | 이벤트의 `ActorId`/`TargetId` 가 가리키는 번호. **이 전투 안에서만 유효** |
| `Team` | `0` 아군 / `1` 적 |
| `TypeId` | **스프라이트를 고르는 열쇠.** 아군은 `characters.json` 의 id(`"C3"`), **적은 `encounters.json` 의 type(`"slime"` `"kappa"` `"eye"` `"mouse"` `"larva"`)** |
| `MaxHp` | 체력바 분모. 전투 중 변하지 않는다 |
| `StartCoordKey` | 시작 좌표 (§3 참조). 이후 위치는 `Move` 로만 바뀐다 |

### 1.2 `GameEvent` — 무슨 일이 일어났는지

`Kind` `Tick` `ActorId` `TargetId` `Value` `Aux` — **전부 int 6개.** 문자열도 객체도 없다.

> **왜 이렇게 앙상한가.** 한 런에 수만 건이 쌓이고 `sim` 은 그걸 수만 런 반복한다.
> 여기에 문자열이 하나 들어가면 틱마다 할당이 생겨 밸런스 루프 처리량이 그대로 깎인다.
> 표시에 필요한 이름·스프라이트는 **전투당 한 번인 `Units` 헤더**가 전달한다.

## 2. 이벤트 표 ★ 이게 계약 본문이다

`Tick` 은 전 항목 공통 — **20틱 = 1초** (고정 틱, `08` §5.2).
`-1` 은 "해당 없음"이다.

| `Kind` | 값 | `ActorId` | `TargetId` | `Value` | `Aux` |
|---|---|---|---|---|---|
| `Move` | 1 | 이동한 유닛 | -1 | **도착** 좌표키 | **출발** 좌표키 |
| `Attack` | 2 | 공격자 | 대상 | `0`=평타 / 스킬 인덱스 | 0 |
| `Damage` | 3 | 가해자 (없으면 -1) | 피해자 | 피해량 | **적용 후 HP** |
| `Shield` | 4 | 부여자 (차감이면 가해자) | 대상 | 변화량 (**차감은 음수**) | **적용 후 보호막 총량** |
| `Heal` | 5 | 시전자 | 대상 | 실제 회복량 (상한 절삭 후) | **적용 후 HP** |
| `Death` | 6 | 처치자 (없으면 -1) | 죽은 유닛 | 0 | 0 |
| `RoundEnd` | 7 | -1 | -1 | `1`=승 / `0`=패 | 0 |
| `StatusApply` | 8 | 시전자 | 대상 | `StatusKind` | **만료 틱(절대값)** |
| `StatusExpire` | 9 | -1 | 대상 | `StatusKind` | 0 |
| `SuddenDeath` | 10 | -1 | -1 | 0 | 0 |

`StatusKind`: `1` Weaken · `2` DotRamping · `3` Invulnerable · `4` Regen · `5` Slow · `6` Root · `7` Shield · `8` Taunt

> ⚠️ **enum 번호는 고정이다.** 중간에 항목을 끼워 넣으면 번호가 밀려 **컴파일은 되는데 화면만 틀린다.**
> 추가는 반드시 맨 뒤. `core.tests/EventLogContractTests.cs` 가 번호를 하드코딩해 CI 에서 막는다.

### 2.1 규칙 3개 — 표보다 이게 중요하다

**① `Aux` 는 언제나 "적용 후 값"이다.**

`Damage` 가 피해량만 준다면 View 는 남은 HP 를 직접 빼야 하고,
그 순간 **피해 규칙(보호막 우선 차감·정수 절삭)이 View 에 복제된다.**
복제된 규칙은 반드시 갈라지고, 갈라지면 **화면과 시뮬이 서로 다른 수치를 말한다.**
→ 체력바·보호막 게이지는 **`Aux` 를 그대로 대입**한다. 빼거나 더하지 않는다.

**② 보호막이 먼저 깎인다.** 같은 틱에 `Shield(-45)` 와 `Damage(0)` 가 같이 오는 게 정상이다.
`Damage.Value == 0` 이라고 무시하면 피격 연출이 사라진다.

**③ 마지막 이벤트는 항상 `RoundEnd` 다.** 재생 종료 판정은 이것 하나로 한다.

## 3. 좌표 — `OrderKey` 하나로 싣는다

보드는 **8×6**, 아군 진영 `x 0..3` / 적 진영 `x 4..7` (`08` §5.1).

```csharp
// 좌표키 → 화면 좌표
int x = key % 8;
int y = key / 8;

// 화면 좌표 → 좌표키 (Core 를 참조할 수 있으면 new Coord(x, y).OrderKey 를 쓴다)
int key = y * 8 + x;
```

> 정수 하나로 접은 이유는 `GameEvent` 를 int 6개로 유지하기 위해서다.
> `Coord` 를 그대로 실으면 필드가 늘고, 늘면 위 §1.2 의 이유가 무너진다.

## 4. 재생 — 이런 모양이 된다

```
t = 0 : Units 로 보드에 유닛을 세운다 (StartCoordKey, MaxHp)
매 프레임:
  playhead += Time.deltaTime * 20 * speed       // 20틱 = 1초. speed 는 View 마음대로
  playhead 를 넘긴 이벤트를 순서대로 소비한다
  Kind 로 분기해 연출만 한다
RoundEnd 를 만나면 정지
```

- **되감기·일시정지·배속은 전부 View 안에서 끝난다.** 로그가 이미 다 있으므로 core 를 다시 부르지 않는다
- 그래서 **연출이 전투 결과에 영향을 줄 수 없다** (`08` §5.5). 이게 이 구조를 택한 이유 전부다
- 같은 틱의 이벤트가 여러 건이면 **리스트 순서가 곧 인과 순서**다. 재정렬하지 말 것

## 5. 지금 바로 시작하는 법 — 전투 코어를 기다리지 않는다

`core/Events/DummyBattleLog.cs` 에 **손으로 적은 가짜 전투 1회**가 들어 있다.

```csharp
using DomoNinja.Core.Events;

BattleLog log = DummyBattleLog.Create();   // 호출할 때마다 같은 내용
```

- Unity 는 이미 `core` 를 UPM(`file:../../core`)으로 참조하고 있다. **추가 세팅 없이 바로 쓰인다**
- **모든 `Kind` 가 최소 1회씩 나온다.** 연출 분기를 전부 미리 만들어 볼 수 있게 그렇게 짰다
- ⚠️ **이건 시뮬레이터가 아니다.** 전투 규칙을 흉내 내지 않았고 수치에 의미가 없다.
  흉내 냈다면 규칙이 두 군데 존재하게 되고, 그 중 틀린 쪽에 연출을 맞추게 된다
- P2 완성 후 실제 로그로 갈아끼우면 이 파일은 지운다

## 6. 로그에 **안** 들어가는 것

| 없는 것 | 어디에 있나 |
|---|---|
| 상점·구매·배타 제거 | 전투 밖. 라운드 사이 개입 지점 (`08` §5.4) |
| 배치 조작 | 전투 시작 전. View 가 결과 좌표만 core 에 넘긴다 |
| 메타 강화·재화 | 런 단위 상태. `meta.json` (`08` §4.5) |
| 유닛 스탯 변화(버프 배율 등) | **의도적으로 뺐다** — §2.1 ① 참조. 결과값만 온다 |

> **없는 걸 View 에서 계산해 채우지 말 것.** 그게 이 경계가 무너지는 유일한 경로다.
> 필요하면 §7 로 요청하면 된다. 이벤트 한 종류 추가는 core 쪽에서 몇 줄이다.

---

## 7. 요청·질문

- 필요한 정보가 로그에 없다 → **어떤 화면을 그리려는지와 함께** T1 에 요청. 추측해서 채우지 않는다
- 재생이 이상하다 → `log.Seed` 와 `Round` 를 같이 보낸다. **그 두 값이면 같은 로그를 재현한다**
