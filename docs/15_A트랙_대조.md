## 1. 🔴 즉시 확인 — 계산이 맞지 않는 지점

### 1.1 `A-5` 타임아웃 디버프 수치

> 원문: **고정 데미지**(최대체력 %, **매틱 적용**): 1% → **30%(상한)**

**매 틱 적용이면 즉사한다.**

| 표기 | 실제 |
|---|---|
| 1% / 틱 | 20틱/초 → **초당 20%** → **5초에 전멸** |
| 30% / 틱 | **초당 600%** → **4틱(0.2초)에 전멸** |

즉 **시작값만으로 5초 안에 끝나고, 30초에 걸친 증가는 발동할 기회조차 없다.**

→ **"매 틱"이 아니라 "매 초"를 의도한 것으로 보인다.** 초 단위면:

| | 초당 데미지 | 전멸까지 |
|---|---|---|
| 시작 (1%/초) | 1% | ~100초 |
| 상한 (30%/초) | 30% | ~3.3초 |

30초에 걸쳐 선형 증가하므로 실제로는 **타임아웃 후 10~20초 내에 결판**난다. 이건 합리적이다.

**확인 필요: 매 틱인가 매 초인가.**

### 1.2 `A-6` 회복 수단이 존재하지 않는다

`A-5`가 **"회복량 감소 50% → 100%"** 를 디버프로 두고 있다. 이건 **회복 시스템이 존재한다는 전제**다.

그런데 `A-6`은 **HP 누적 · 부활 없음**이고, 현재 `/data/economy.json` 상점 품목은 **스킬 활성화 / 스킬 강화 / 스탯 강화** 3종뿐이다.
**회복 수단이 어디에도 없다.**

→ 셋 중 하나를 골라야 한다.
1. 상점에 **회복 아이템** 추가 (경제 재설계 필요)
2. 스킬 중 일부에 회복 부여 (`C2` 수도승 계열이 후보)
3. `A-5`의 "회복량 감소" 항목 삭제

### 1.3 보드 `4×6` 의 해석

24칸이다. **한 진영이 4×6인가, 양 진영 합쳐 4×6인가.**

- 아군 3명 + 적 최대 6체(현재 `encounters.json` 기준) = 9유닛
- 전체가 4×6이면 유닛 밀도가 낮아 **이동만 하다 전투가 늘어진다** → `A-5` 타임아웃에 자주 걸릴 수 있다
- 진영별 4×6(총 4×12)이면 지나치게 넓다

**확인 필요: 정확한 필드 형태와 양 진영 시작 위치.**

## 2. ⚠️ 갈린 결정 6건과 그 파급

### 2.1 `A-1` 이동 — **있음** (내 추천: 없음)

정수 좌표 그리드, 그리디 1스텝(dx/dy 중 큰 축 우선, 동률 x축), 보드 4×6.

| 영향 | 내용 |
|---|---|
| 결정론 | ✅ 문제없음. 정수 좌표 + 처리 순서 + 점유 충돌까지 규정됨 |
| 부동소수점 | ✅ 여전히 불필요 (정수 제곱거리 비교) |
| 구현량 | ⬆️ 증가. 다만 그리디 1스텝이라 경로탐색이 없어 감당 가능 |
| **시뮬 속도** | ⚠️ 유닛당 매 틱 이동판정이 추가된다. **16,000런 × 틱 수**에 직접 곱해진다 |
| **빌드 공간** | 🔴 **배치가 변수로 추가된다** → §3 참조 |

### 2.2 `A-3` 전열/후열 폐기 — 자유 배치 + 정수 제곱거리 (내 추천: 2단계)

🔴 **이게 우리 데이터에 가장 큰 타격이다.**

| 무효화되는 것 | 위치 |
|---|---|
| `placementRule` (전열 피해감소 / 후열 공격증가) | `characters.json` |
| **`frontlineAffinity` 스탯 자체** | `characters.json` 6명 전원 |
| `range: 1 = 적 전열만 / 2 = 적 후열까지` 정의 | 스키마 §2 |
| **`C3-B 표창`** "후열에서도 공격 가능" | `skills.json` |
| **`C4-A 저격`** "적 후열 우선 타격" | `skills.json` |
| `targeting.priority: backline_first` | 스키마 §3 |

→ `range` 를 **정수 제곱거리 임계값**으로 재정의하고, 위 2개 스킬을 **거리 기반으로 재설계**해야 한다.
→ `frontlineAffinity` 는 폐기하거나 **"이동 속도 / 선제 돌진 성향"** 같은 다른 의미로 전환해야 한다.

### 2.3 `A-5` 종료조건 — 전멸 or 타임아웃 후 점증 디버프 (내 추천: 타임아웃 시 HP 총합 판정)

**설계 의도는 이쪽이 낫다.** HP 총합 비교는 판정이 임의적인데, 서든데스 디버프는 **반드시 전멸로 끝나므로 승패가 자연스럽다.**
→ 채택 권고. 단 §1.1 수치 확인 후.

### 2.4 `A-6` HP 누적 · 부활 없음 (내 추천: 매 라운드 완전 회복) 🔴

**가장 큰 게임 성격 변화다.**

| 우려 | 내용 |
|---|---|
| **이중 실패 시스템** | 생명 3 + HP 누적 + 부활 없음. 유닛이 죽으면 남은 라운드를 2명으로 치러야 하는데 그건 사실상 런 종료다 → **생명 시스템이 유명무실해진다** |
| **`M1` 달성 난이도** | 클리어율 목표 35~55%를 맞추기가 훨씬 어려워진다 |
| **`M2` 해석 오염** | "라운드별 패배율 분포"로 난이도 곡선을 보는데, 누적이면 앞 라운드 상태에 오염되어 **곡선을 읽을 수 없다** |
| **회복 부재** | §1.2 |

**대안 (구조를 바꾸는 쪽):**
- **라운드 종료 시 부분 회복** (예: 최대 HP의 40%) + 사망 유닛은 다음 라운드에 **HP 30%로 부활**
- 자원 관리 긴장은 유지하면서 런이 조기 사망하지 않는다
- 회복 아이템을 넣지 않아도 되고, `M2` 해석도 상당 부분 회복된다

### 2.5 `A-7` 스킬 발동 — 주기 쿨다운 + 보조는 상시 패시브

🔴 **우리 `skills.json` 12개와 구조가 다르다.**

- 우리 스킬은 `stat_mult`(상시) / `conditional`(트리거) / `status` 조합이고 **쿨다운 개념이 없다**
- A 트랙은 **"기본 스킬(주기 쿨다운)" + "보조 선택 스킬(패시브)"** 2계층을 전제한다
- ⚠️ **이 2계층이 우리 「캐릭터당 스킬 2택」 배타 구조와 어떻게 맞물리는지 불명확하다**
  - 2택이 "기본 스킬 2개 중 택1"인가?
  - 아니면 기본 스킬은 고정이고 보조만 2택인가?

**확인 필요.** 후자라면 배타 선택의 무게가 크게 줄고, 빌드 공간 160의 의미도 달라진다.

> 쿨다운을 틱 정수로 저장하라는 지적(`N×20`, float 누적 금지)은 정확하다. 스키마 §7에 이미 같은 취지가 있다.

### 2.6 `A-10` 아이템 4종 — 캐릭터 지정 / 전체 / **직군** / 조건부

- `/data/economy.json` 의 `statBoost` 는 **캐릭터 지정 1종만** 있다 → 확장 필요
- 🔴 **"직군" 개념이 우리 설계에 없다.** `08` §2.5는 하드 클래스를 의도적으로 배제하고 `frontlineAffinity` 연속 스탯으로 갔다
  → 직군을 도입하려면 6명에 클래스 태그를 부여해야 하고, 이는 `M3a`(출전률 20~80%) 설계 논거와 충돌할 수 있다
- ✅ **합연산 규칙(퍼센트 전부 더한 뒤 마지막에 1회 곱)은 좋다.** 결정론·예측가능성·정수 연산에 모두 유리하다. 스키마에 명시할 것

## 3. 🔴 파급 — 빌드 공간과 `M4` 계산

`08` §6.1의 전제가 흔들린다.

```
기존:  로스터 20 × 스킬 2택 8 = 160 빌드 → 전수 탐색 → M4를 정확값으로 계산
```

**`A-1`(이동) + `A-3`(자유 배치)로 배치가 변수가 됐다.** 4×6 보드에 3명을 놓는 경우의 수가 붙는다.

→ 세 가지 중 하나를 택해야 한다.

1. **배치를 빌드에 포함시키지 않는다** — 시뮬은 각 빌드마다 **고정된 배치 규칙**(예: 사거리 짧은 순으로 앞)을 쓴다. 160 전수 탐색이 그대로 유지된다 ← **권고**
2. 배치까지 탐색 → 공간이 수십만으로 폭발. 전수 탐색 포기, 샘플링으로 후퇴 → **`M4`가 정확값에서 추정치로 격하된다**
3. 배치를 소수의 프리셋(예: 3~5종)으로 제한 → 160 × 5 = 800. 전수 유지 가능

> **`M4`를 "추정이 아니라 정확값"으로 말할 수 있다는 게 `D-30` 채택의 결정적 근거였다.** 여기를 잃으면 안 된다.
> 1번 또는 3번으로 방어할 것.
