# `/tune` — 밸런스 외부 최적화 루프

> **여기에는 게임 로직이 한 줄도 없다** (`D-49-a`).
> `sim`(C#)이 `params.json → metrics.json` CLI 이므로, 이 층은 그 바이너리를 **호출만 한다.**
> 결정론은 C#, 통계는 Python — **언어를 나눈 게 아니라 역할을 나눈 것이다.**

## 왜 나뉘어 있나

C# 에 쓸 만한 블랙박스 탐색기가 없었다(`17` §8 — CMAES.NET 은 2020년 방치, Math.NET 은 국소·미분 기반).
Optuna(★14.6k)와 SALib 이 있는 쪽으로 **탐색만** 옮겼다.

**대가로 생긴 위험은 하나다** — 게임이 Python 에 기대기 시작하는 것.
`balance.yml` 의 첫 job 이 그걸 막는다: `core`·`sim` 은 외부 프로세스를 띄우지 않고,
패키지 의존은 `Newtonsoft.Json` 하나뿐이다.

## 파일

| | |
|---|---|
| `space.py` | **이 디렉토리의 유일한 게임 지식.** 어느 값을 얼마나 흔들지 |
| `evaluate.py` | `sim` 호출 → 목적함수 `D` |
| `screen.py` | Morris 스크리닝 — 어느 축을 탐색할지 **측정으로** 고른다 |
| `optimize.py` | Optuna ask-and-tell + 축차 반감법 |
| `reports/` | 실행 산출물. **커밋한다** (`D-49-b`) |

> **`space.py` 만 갈아끼우면 다른 장르에서도 그대로 돈다.**
> 나머지는 "파라미터 이름과 범위" 만 알면 되고 게임이 무엇인지 모른다 — `05` §1.6 이 요구한 형태다.

## 쓰는 법

```bash
# 0. sim 을 Release 로 빌드해둔다 (Debug 로 재면 처리량 판정이 배포본과 어긋난다)
dotnet build sim/DomoNinja.Sim.csproj -c Release

# 1. 설치 (최초 1회)
py -m venv tune/.venv
tune/.venv/Scripts/python.exe -m pip install -r tune/requirements.lock

# 2. 어느 축이 실제로 영향이 있는지 measure
tune/.venv/Scripts/python.exe tune/screen.py --trajectories 10

# 3. 상위 축만 탐색
tune/.venv/Scripts/python.exe tune/optimize.py --trials 60 --top-k 12
```

## 이 층이 지키는 세 가지

### ① `/data` 파일을 고치지 않는다

수천 번 값을 시도하는데 그때마다 파일을 쓰면 **중간에 멈췄을 때 저장소가
어느 시도의 값으로 남아 있는지 알 수 없다.** `sim` 의 `overrides` 로 메모리에서만 덮어쓴다.

> **채택된 값만 사람이 `[BAL]` 커밋으로 넣는다** (`09` §7).
> `balance.yml` 도 자동 커밋하지 않고 리포트를 아티팩트로 올린다 —
> **기계가 자기 결과를 자기가 커밋하면 "무엇을 사람이 판단했는가" 가 로그에서 사라진다.**

### ② 조용히 실패하지 않는다

덮어쓰기 경로가 안 맞으면 `sim` 이 **종료 코드 4** 로 멈추고, `evaluate.py` 가 그걸 예외로 올린다.

> 삼키면 최적화기는 **값을 바꿨다고 믿고**, 지표가 안 움직인 걸
> *"그 파라미터는 영향이 없다"* 로 학습한다. **Morris 결과가 통째로 거짓말이 된다.**

### ③ 예산 축은 **시드**다 — 빌드가 아니다

```
seeds=1 builds=200   D = 0.0000      seeds=1 builds=all   D = 0.6371
seeds=3 builds=200   D = 0.0000      seeds=3 builds=all   D = 0.6369
```

★ **`M3a`·`M3b`·`M3c` 가 빌드 공간 위에서 정의된 지표**라서다.
빌드 열거가 체계적이라 앞쪽 N 개는 같은 캐릭터를 공유한다 — 잘라내면
*"사장된 선택지"* 가 통계가 아니라 **자르는 위치의 함수**가 되고,
기하평균이라 그 하나가 전체를 0 으로 만들어 **기울기가 통째로 사라진다.**

> 축차 반감법(`17` §3)의 저예산 단계를 **"표본을 줄이는" 쪽으로 만들면 안 되는 경우**가 있다는 뜻이고,
> 이건 장르 비의존적인 교훈이다 — **지표가 표본 공간 자체 위에 정의돼 있으면 그 공간은 예산 축이 못 된다.**
> 전수 4,320 빌드가 시드 1개에 0.8초라 예산 문제도 아니었다.

## 읽을 때 조심할 것

**Morris 가 "영향 없음" 으로 잡는 것이 전부 게임의 성질은 아니다.**
아이템 가격 4종의 μ\* 가 0 인 건 **봇이 아이템을 안 사기 때문이다**(`08` §6.1 — 빌드 공간이 스킬만).
*"영향이 없으니 빼도 된다"* 로 읽으면 **실제 플레이에서만 작동하는 축을 지우게 된다.**
`M6` 을 뺀 것(`D-72`)과 같은 계열이고, 리포트의 `_botPolicyNote` 에 박아뒀다.
