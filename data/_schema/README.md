# `/data` 스키마 계약

작성일: 2026-07-31 / 개정: 2026-08-01 (v0.5)
대응: `08_게임_스펙.md` §3 · §7 · §11 / 핸드오프 **H1** (`12_작업분담.md` §4)

> **이 문서가 `/core` `/sim` `/unity` 세 곳이 공유하는 계약이다.**
> 스키마 변경은 사람이 결정하고, **값 변경은 최적화기·AI가 한다.**
> 로드 시 검증에 실패하면 **즉시 에러**. 조용히 기본값으로 넘어가지 않는다.

> **v0.5 개정 — A 트랙 확정(`A-1`~`A-10`) 반영.**
> 전열/후열이 폐기되고 좌표·이동이 들어왔다. 바뀐 곳은 §2(스탯) · §3(targeting) · §7(결정론) · §9(합연산) · §10(보조 스킬).
> **템플릿 5종은 그대로다.** 회복도 쿨다운도 기존 템플릿 안에서 표현된다 — 새 템플릿을 늘리지 않았다.

## 1. 파일

| 파일 | 내용 | 누가 바꾸나 |
|---|---|---|
| `characters.json` | 로스터 6명 기본 스탯·스프라이트·딜레마 축 | 값: 최적화기 |
| `skills.json` | 액티브 스킬 12개 + **보조 스킬 6개** | 값: 최적화기 |
| `encounters.json` | 적 타입 정의 + 8라운드 관문 구성(**좌표**) | 값: 최적화기 / 구성: 사람 |
| `economy.json` | **런 전용** 구조·보드·전투 파라미터·재화·상점·가격·회복 | 값: 최적화기 |
| `meta.json` | **런 사이 영구 강화**(메타 프로그레션)·영구 재화·저장 정책 | 값: 최적화기 |
| `balance.json` | *(시뮬 산출물)* 현재 밸런스 스냅샷 + M1~M7 | 시뮬이 생성 |

> ★ **`economy.json` 과 `meta.json` 은 화폐가 다르다.** 전자는 런 전용(종료 시 소멸), 후자는 영구.
> **둘을 섞지 않는다** — 섞으면 "런 안에서 잘하기"와 "런을 반복하기"가 같은 자원을 두고 경쟁해 밸런스 해석이 불가능해진다.

**코드에 상수를 박지 않는다.** 이 파일들이 곧 최적화기와 AI가 조정할 표면이다.

## 2. 스탯 이름 (전역 공통)

| 이름 | 의미 | 형 |
|---|---|---|
| `hp` | 최대 체력 | int |
| `attack` | 1회 타격 피해 | int |
| `attackInterval` | 공격 간격(틱). **낮을수록 빠르다** | int |
| `range` | **사거리(칸).** 판정은 정수 제곱거리 | int |
| `moveInterval` | **이동 1칸당 틱. 낮을수록 빠르다** | int |
| `damageTaken` | 받는 피해 배율 (스킬 전용 가상 스탯) | float |
| `skillPower` | **선택한 메인 스킬의 위력 배율** (보조 스킬 전용 가상 스탯) | float |

> `skillPower` 는 v0.6 신설. **보조 스킬이 「선택한 메인 스킬」을 강화하기 위한 우회로**다(`A3`).
> 이게 있어야 보조 3종을 액티브 A/B와 무관하게 하나로 쓸 수 있다 — **저작 물량이 36 → 18로 반이 된다.**
> `target: "mainSkill"` 로 지정한다.

> **v0.4 → v0.5 변경 2건**
> - `range` 가 `1=전열만 / 2=후열까지` 라는 2단계 열거값에서 **연속적인 칸 수**로 바뀌었다 (`A-3`)
> - `frontlineAffinity` 폐기 → **`moveInterval` 신설** (`A-1`). 전열/후열 규칙이 사라져 갈 곳이 없어졌다

**사거리 판정 — 부동소수점 금지**

```
사거리 안에 있다  ⟺  dx*dx + dy*dy  <=  range*range
```

`sqrt` 는 **비교에 절대 쓰지 않는다.** 표시용으로 필요할 때만 렌더링 레이어에서 계산한다.

**진형은 규칙이 아니라 스탯의 귀결이다**

`placementRule`(전열 피해감소 / 후열 공격증가)은 삭제됐다. 대신:

```
moveInterval 짧음 + range 짧음  →  먼저 붙는다  →  자연스럽게 전열
moveInterval 긺   + range 긺    →  뒤에 남는다  →  자연스럽게 후열
```

하드 규칙 없이 진형이 생기고, **밸런스 조정도 두 스탯의 값만 만지면 된다.**

## 3. 스킬 효과 템플릿 — **5종. 새 템플릿을 늘리지 않는다**

스킬 하나는 `effects` 배열을 갖고, 각 원소가 템플릿 1개 적용이다.

### `stat_mult`
```json
{ "template": "stat_mult", "target": "self", "stat": "attack", "value": 1.5,
  "stacking": false, "maxStacks": 1 }
```
`target`: `self` / `allies` / `allies_except_self` / **`lowestHpAlly`** / `enemy` / `all_enemies` / `mainSkill`

> `lowestHpAlly` (v0.8) — 현재 HP **비율**이 가장 낮은 아군. 동률이면 슬롯 인덱스 오름차순.
> 절대값이 아니라 비율인 이유: 체력 180인 수도승과 80인 주술사를 절대값으로 비교하면 항상 주술사만 회복된다.

### `aoe`
```json
{ "template": "aoe", "scope": "adjacent", "value": 0.5 }
```
`scope`: `adjacent` / `radius`(+`value`) / `all_enemies` / `multi_target`(+`targetCount`)
`damageSource`: 생략 시 `attack`. `maxHp` 지정 가능(파동)

> `row`(같은 행) 는 삭제. 좌표가 생겼으므로 `radius` 가 더 자연스럽고 제곱거리로 판정된다.

### `conditional`
```json
{ "template": "conditional",
  "trigger": { "type": "on_kill" },
  "effect": { "template": "extra_attack", "count": 1 } }
```
`trigger.type`: `on_kill` / `on_damaged` / `on_dodge` / `on_hit` / `hp_below`(+`value`) / `every_n_tick`(+`value`)
중첩 `effect`는 위 템플릿 또는 아래 원자 동작: `extra_attack` / `counter` / `recast`(+`maxChain`) / `self_damage` / **`heal`**

> **`on_hit`** (v0.8) — 자신의 공격이 적중한 순간. 흡혈·표식·둔화 부여의 트리거다.
> `on_damaged`(피격당함)와 반대 방향이므로 헷갈리지 말 것.

**`heal` 원자 동작** (v0.8)
```json
{ "template": "heal", "target": "allies", "permille": 60 }
{ "template": "heal", "target": "lowestHpAlly", "fromDamagePermille": 250 }
```
- `permille` — **대상 최대 체력**의 천분율
- `fromDamagePermille` — 방금 발생한 **피해량**의 천분율 (흡혈·전환형)
- 둘 중 하나만 쓴다. 회복량은 정수 절삭한다
- **사망 유닛에는 적용되지 않는다** (`A6` — 부활 없음)

> ★ **`A-7`의 "주기 쿨다운"은 `every_n_tick` 이 이미 표현한다.**
> 액티브/패시브를 가르는 별도 필드를 두지 않는다. 발동 방식은 스킬 데이터가 정한다.
> 쿨다운 값은 **반드시 틱 정수**로 저장한다. 초 단위 float 누적 금지(`A-7` 구현 주의).

### `status`
```json
{ "template": "status", "target": "all_enemies", "kind": "weaken",
  "attackMult": 0.85, "damageTakenMult": 1.15, "duration": 200 }
```
`kind`: `weaken` / `dot_ramping`(+`baseValue`,`rampPerTick`) / `invulnerable_first_hit` / `regen`(+`healPermille`,`everyTicks`) / `slow`(+`moveIntervalMult`) / `root` / **`shield`** / **`taunt`**

> `root` 는 v0.6 신설 — `A5`가 **"상태이상으로 움직임이 제한된 경우"** 를 이동의 예외로 명시했다.
> `slow`(느려짐)와 `root`(못 움직임)는 다르다. 둘 다 공격은 가능하다.

### `shield` (v0.8) ★

```json
{ "template": "status", "target": "self", "kind": "shield",
  "gainPermille": 80, "maxPermille": 350,
  "overflowToHp": true, "refreshEveryTicks": 200, "whileStationary": false }
```

| 필드 | 의미 |
|---|---|
| `gainPermille` | 1회 획득량 (**최대 체력**의 천분율) |
| `maxPermille` | 보호막 상한 |
| `overflowToHp` | **상한 초과분을 체력으로 전환**한다. `false`면 버려진다 |
| `refreshEveryTicks` | 주기적으로 상한까지 재충전 (생략 시 트리거로만 획득) |
| `whileStationary` | `true`면 **이동하지 않는 동안만** 유지된다 |

**처리 규칙 — 결정론상 순서를 고정한다**

```
피해 발생 → ① 보호막에서 먼저 차감 → ② 남은 피해를 HP에서 차감
회복 발생 → HP만 회복한다. 보호막은 회복 대상이 아니다
overflowToHp → 초과분을 HP에 더하되 최대 체력을 넘지 않는다
```

- 보호막은 **`damageTaken` 배율을 적용한 뒤의 피해**를 흡수한다. 순서를 뒤집으면 결과가 달라진다
- 라운드 종료 시 **보호막은 사라진다.** HP만 누적된다(`A-6`)

### `taunt` (v0.8) ★

```json
{ "template": "status", "target": "self", "kind": "taunt", "threatMult": 3.0 }
```

**적의 타겟팅 우선순위를 바꾼다.** ⚠️ 결정론상 순서를 명시적으로 고정한다:

```
① 어그로(taunt) 보유 아군 중 threatMult 가 가장 높은 대상
② 동률이거나 어그로 보유자가 없으면 → 최근접
③ 그래도 동률이면 → 슬롯 인덱스 오름차순
```

- **사거리 밖의 어그로 대상은 무시한다** — 안 그러면 적이 닿지도 않는 대상만 보며 멈춘다
- 어그로 보유자가 죽으면 즉시 ②로 내려간다

> **회복은 `regen` 하나로 끝난다.** 신규 템플릿이 필요 없었다.
> `healPermille` 은 **최대 체력의 천분율**이며 정수다. 실제 회복량 = `maxHp * healPermille / 1000` (정수 나눗셈).

### `targeting`
```json
{ "template": "targeting", "priority": "farthest", "setRange": 7, "rangeBonus": 2 }
```
`priority`: `nearest`(기본) / `lowest_hp` / **`farthest`**
`setRange`(절대값 지정) 와 `rangeBonus`(가산) 는 다르다 — 보조 스킬은 **가산**을 쓴다. 합연산 규칙(§8) 대상이다.

> `backline_first` 는 **삭제**됐다(`A-3`으로 후열이 없어짐). `farthest` 가 그 의미를 이어받는다 — 가장 먼 적 우선.
> 동률이면 §7의 슬롯 인덱스 오름차순으로 깬다.

## 4. 강화 = 보조 스킬 (`A3`) — **v0.6에서 `upgrades` 폐기**

> **3단계 누적 강화(`upgrades`)를 삭제하고 보조 스킬로 통합했다.**
> `A3` 회신이 *"보조스킬 == 선택한 메인 스킬을 강화하는 패시브 스킬 개념"* 이라고 정의했으므로 **두 시스템이 같은 것**이다.

| | v0.5 (폐기) | **v0.6** |
|---|---|---|
| 형태 | `upgrades` 레벨 1→2→3 누적 | **캐릭터별 보조 3종 중 최대 2 선택** |
| 성격 | 같은 방향으로 수치가 오른다 | **양상이 갈린다** (오버워치 특전 개념) |
| 저장 위치 | 액티브 스킬 객체 내부 | `skills.json.supportSkills` |

**얻는 것**

- **시스템이 하나 줄었다.** 상점 품목이 액티브/강화/보조 3종 → 액티브/보조 2종
- 배타 선택이라는 정체성과 맞는다 — 수치가 오르는 게 아니라 **또 한 번 갈린다**
- ⚠️ 다만 **`M4b`(비추이성) 관측 대상이 늘었다.** 보조 선택까지 관문별로 정답이 달라야 좋다

> ⚠️ **이건 우리 해석이다.** `Q4`는 "강화 패시브"와 "보조 스킬"을 따로 말한 것처럼 읽히고 `A3`는 같다고 읽힌다.
> **별개 시스템이면 되돌려야 한다** — `temp/03` 후속 확인 항목.

## 5. 태그 자동 생성 — **`tags` 필드를 신뢰하지 않는다**

`skills.json` 의 `tags` 는 **검증용 기대치**다. 런타임 표시는 `effects` 에서 파생한다.

| 조건 | 태그 |
|---|---|
| `template: aoe` | `#광역` |
| 단일 대상 + `value >= 1.5` | `#단일` |
| `status` 이면서 `target` 이 적 | `#디버프` |
| `stat_mult` 이면서 `target` 이 아군 | `#버프` |
| `trigger.type: on_kill` | `#처치시` |
| `trigger.type: on_damaged` | `#피격시` |
| `trigger.type: every_n_tick` | **`#주기`** |
| `targeting.setRange` 존재 | `#사거리` |
| `stat: attackInterval` 이고 `value < 1` | `#공속` |
| `stat: moveInterval` 이고 `value < 1` | **`#기동`** |
| `kind: dot_ramping` | `#지속딜` |
| `kind: regen` | **`#회복`** |

표시는 2~3개까지, 회색 소형 폰트로 하단 배치.
**밸런스 패치로 스킬이 바뀌면 태그가 자동으로 따라온다** → 데이터와 표기가 어긋날 수 없다.
부수 효과로 밸런스 리포트의 분류 축이 생긴다 (`#광역 계열 평균 채택률` 등).

## 6. 로드 시 검증 규칙 (실패하면 에러)

- [ ] 캐릭터 수 == `economy.roster.poolSize`
- [ ] 모든 캐릭터가 **정확히 2개**의 액티브 스킬을 갖는다
- [ ] 모든 스킬(액티브·보조)에 `text.gain` 과 `text.cost` 가 **둘 다** 있다 → **한쪽이 그냥 좋은 스킬 금지**(`M3b`)
- [ ] **모든 캐릭터가 정확히 `poolPerCharacter`(=3)개의 보조 스킬을 갖는다**
- [ ] **각 캐릭터의 보조 3종이 `slot` 을 `공격`·`생존`·`팀` 하나씩 갖는다** (§10 3자리 문법)
- [ ] 모든 액티브 스킬에 `role` 이 있고, `퓨어딜러`/`브루저`/`탱커`/`힐러`/`디버퍼`/`버퍼` 중 하나다
- [ ] **`shield` 에 `overflowToHp` 가 있으면 `maxPermille` 도 있다** (상한 없이 초과분을 정의할 수 없다)
- [ ] `heal` 에 `permille` 과 `fromDamagePermille` 중 **정확히 하나만** 있다
- [ ] **어떤 액티브 스킬에도 `upgrades` 필드가 없다** (v0.6에서 폐기 — 남아 있으면 마이그레이션 누락)
- [ ] `effects[].template` 이 §3의 5종 안에 있다
- [ ] `trigger.type` · `status.kind` · `targeting.priority` 가 §3의 목록 안에 있다
- [ ] `encounters.rounds` 가 1~8을 빠짐없이 덮는다
- [ ] 모든 `variants[].units[].type` 이 `enemyTypes` 에 존재한다
- [ ] **모든 적 좌표가 적 진영 범위 안이다** (`x` ∈ [cols, 2*cols-1], `y` ∈ [0, rows-1])
- [ ] **한 variant 안에서 좌표가 중복되지 않는다**
- [ ] `variants[].units` 의 수 <= 자기 진영 칸 수(`cols * rows`)
- [ ] `supportSkills` 수 == 캐릭터 수 × `economy.shop.supportSkill.poolPerCharacter`
- [ ] 모든 보조 스킬의 `character` 가 `characters.json` 에 존재한다
- [ ] `moveInterval >= 1` (0이면 무한 이동). **단 `immobile: true` 인 적은 `moveInterval` 이 없어도 된다**
- [ ] `immobile: true` 는 `enemyTypes` 에만 나타난다 (`A5` — 고정포대는 적 전용)

### 6.1 구현하며 추가된 규칙 2건 (2026-08-02)

위 20개는 스키마가 정한 것이고, 아래 둘은 **코드를 짜다 구멍이 보여서 더한 것**이다.

- [ ] **`R21`** — `board.perSide` 가 `Coord` 의 보드 크기 상수와 일치한다
  > `Coord` 는 정수 연산·배열 인덱싱 때문에 보드 크기를 `const` 로 들고 있다.

## 7. 결정론 요구사항 (`05_결정사항.md` §2.4)

이 데이터를 소비하는 코어는 아래를 지켜야 한다.

- **부동소수점을 쓸 자리가 없어야 한다.** 좌표는 정수, 거리는 **정수 제곱거리**, 시간은 틱 정수 누적, HP·피해는 정수
  - 배율(`value: 1.5`)은 **정수 연산 후 절삭**으로 적용한다. 누산 순서를 고정할 것
  - 서든데스 램프는 천분율 정수 나눗셈 (`economy.combat.suddenDeath._formula`)
- `System.Random` 금지 → **시드 주입형 자체 PRNG**
- `Dictionary`/`HashSet` 순회 결과에 의존 금지 → `List` + 명시적 정렬
- 동률 타이브레이크는 **슬롯 인덱스 오름차순**으로 고정
- CI 회귀 테스트: **같은 시드 2회 실행 → 결과 해시 동일**

### 7.1 이동 규칙 (`A-1` 신설)

매 틱, **슬롯 인덱스 오름차순**으로 고정 순회하며 유닛마다 **이동 판정 → 공격 판정** 순으로 처리한다.

- 목표까지 `dx`/`dy` 중 **차이가 큰 축을 먼저 축소**. 동률이면 **x축 우선**(고정)
- 그리디 **1스텝**. 경로 탐색 없음
- 이동 목표 칸이 겹치면 **먼저 처리된 유닛이 점유**하고, 나중 유닛은 그 틱은 **정지**
- 유닛은 `moveInterval` 틱마다 **1칸** 움직인다 (`A2` 확정: 한 번의 이동 = 한 칸). 잔여 틱은 **정수 누적**으로 관리한다
- **사거리 안에 표적이 있으면 이동하지 않는다** (붙어야만 때리는 게 아니다)
- **적·아군 모두 이동한다** (`A5`). `encounters.json` 의 좌표는 **시작 위치**다
- 이동하지 않는 예외 **둘뿐**:
  1. `status.kind: root` 가 걸린 유닛
  2. `immobile: true` 인 적 (고정포대형). **적 전용이며 이동 판정 자체를 건너뛴다**
- 플레이어가 이동에 관여하는 지점은 **라운드 시작 전 배치뿐이다** (`A5`·`A-8`). 전투 중 이동은 전부 자동

> 좌표가 정수이므로 이동이 생겨도 **부동소수점은 여전히 불필요하다.**
> → `13_외부도구_조사.md` §2.2 FixedMathSharp **불채택 판단은 유지된다.**

## 8. 합연산 규칙 (`A-10` 신설) ★

퍼센트 증감은 **곱하지 않고 전부 더한 뒤, 마지막에 한 번만 적용**한다.

```
잘못:  attack * 1.5 * 1.2 * 0.9        (곱연산 — 순서에 따라 절삭 결과가 달라진다)
맞음:  attack * (1 + 0.5 + 0.2 - 0.1)  (합연산 — 순서 무관)
```

- **결정론**: 절삭 지점이 1회뿐이라 누산 순서 의존이 사라진다
- **예측가능성**: 플레이어가 상점에서 계산할 수 있다
- **밸런스**: 곱연산은 버프를 겹칠수록 폭발해 `M4` 지배 빌드를 만든다

적용 대상: `stat_mult`, `items.*`, 보조 스킬의 스탯 증감 전부.
`damageTaken` 같은 감소 계열도 동일하게 **합산 후 1회 적용**한다.

## 9. 회복 (`Q2`·`Q6` 확정) ★

회복은 **3층**이고 각 층의 출처가 다르다. `economy.healing` 참조.

| 층 | 출처 | 시점 | 재화 |
|---|---|---|---|
| 1 | 라운드 승리 자동 회복 | 라운드 종료 | 불필요 |
| 2 | 상점 회복 아이템 | 구매 즉시 | 필요 |
| 3 | **`C6-B` 가호** (캐릭터 액티브) | **전투 중** | 1회 구매 |

- **부활은 어디에도 없다** (`A6` 확정). 사망 유닛은 런 종료까지 돌아오지 않는다. **상점 부활 아이템도 없다**
- **`A-5` 회복량 감소 디버프가 실제로 감소시키는 것은 3층뿐이다.** 1·2층은 전투 밖에서 일어난다
- 전투 중 사용하는 소모품은 없다 — `A-8`(개입 지점은 배치와 상점뿐)을 지키기 위함

> ★ **v0.6 변경**: 3층이 보조 스킬 `S1 재생` → **캐릭터 액티브 `C6-B` 가호**로 옮겨졌다.
> `A3`로 보조 스킬이 「메인 강화」가 되면서 독립 회복 스킬이 들어갈 자리가 사라졌고,
> 팀원이 *"기본적으로 회복을 스킬로 가진 유닛이 존재함"* 이라고 명시했기 때문이다.
>
> ⚠️ **전투 중 회복이 `C6-B` 하나뿐이라 `C6`이 준필수 픽이 될 위험이 있다** → `M3a`(출전률 20~80%) 감시.
> 넘으면 1층 회복량을 올리거나 회복 아이템을 싸게 한다. **캐릭터를 늘려 푸는 게 아니라 다른 층으로 푼다.**

## 10. 보조 스킬 (`A3` 확정 — v0.6 전면 재설계)

**캐릭터별 3종, 그중 최대 2개 선택. 선택한 메인(액티브) 스킬을 강화한다.** `skills.json.supportSkills`.

| 항목 | 값 |
|---|---|
| 귀속 | **캐릭터별** (v0.5의 "런 단위 독립"에서 뒤집힘) |
| 캐릭터당 풀 | **3** |
| 최대 선택 | **2** |
| 총 개수 | 6 × 3 = **18** |
| 선행 조건 | **메인 액티브를 활성화한 뒤에야** 그 캐릭터의 보조가 풀에 진입한다 |
| 가격 | 1번째 4 / 2번째 6 |

**왜 「액티브별」이 아니라 「캐릭터별」인가 — 물량 제약**

액티브별로 두면 12 × 3 = **36개**를 저작해야 한다. 실질 구현 기간 일주일에 불가능하다.
→ 캐릭터별 3종을 두고, 효과는 **가상 스탯 `skillPower`(§2)를 경유해 「그 런에서 선택한 메인 스킬」에 적용**한다.
액티브 A를 골랐든 B를 골랐든 같은 3종이 나온다. **팀원 의도(메인 강화)는 보존되고 물량은 반이 된다.**

### v0.8 — 3자리 문법 ★

**전 캐릭터의 보조 3종이 같은 자리 구조를 갖는다.**

| 자리 | 성격 | 예 |
|---|---|---|
| **P1 공격** | 위력 / 속도 / 사거리 | 극 · 소신 · 비도 · 관통 · 심화 · 공명 |
| **P2 생존** | 보호막 / 피해감소 / 체력 | 불굴 · 금강 · 잔영 · 참호 · 결계 · 정심 |
| **P3 팀 기여** | 회복 / 버프 / 어그로 | 호령 · 자애 · 연막 · 표식 · 흡정 · 광명 |

캐릭터당 **최대 2개**를 고르므로 `공+생` / `공+팀` / `생+팀` 세 갈래가 된다.

> ★ **이 문법이 해결한 것**: v0.7까지 보조 18개 중 15개가 공격 계열이었다.
> 메인 12 + 보조 18 = **30 슬롯 중 탱힐이 5개**뿐이었다.
> 3자리 문법으로 **18개**가 됐고, 무엇보다 **6명 전원이 탱 옵션과 힐 옵션을 하나씩 갖는다**
> → **탱/힐이 0인 3인 조합이 사라진다.**

⚠️ **`P1`이 항상 정답이 될 위험**이 있다 — 딜이 없으면 못 이기기 때문이다.
`M3c`(보조 채택률)로 감시하고, **딜 수치·적 수치 조정으로 푼다.** 구조를 바꾸지 않는다.

전부 `text.gain` + `text.cost` 를 갖는다. 액티브와 같은 문법이다(`M3b`).

## 10.5 메타 프로그레션 (`meta.json`) — v0.7 신설 ★

**뱀파이어 서바이버즈식 메인메뉴 공용 스탯 강화.** 런 사이에 남는 영구 재화로 전 캐릭터 공통 스탯을 올린다.

| 항목 | 규칙 |
|---|---|
| 대상 | **전 캐릭터 공용.** 캐릭터를 지정하지 않는다 |
| 화폐 | `metaCurrency` — 런 재화와 **별개** |
| 획득 | 도달 라운드당 2 + 클리어 시 10. **패배해도 진전이 남는다** |
| 항목 | 6종 (공격/체력/공속/기동/회복/재화), 각 3~5단계 |
| 연산 | 합연산(§8)에 참여. 런 내부 버프와 더한 뒤 마지막에 1회 곱 |

**왜 캐릭터를 지정하지 않는가** — 지정하면 강화된 캐릭터가 준필수 픽이 되어 **`M3a`(출전률 20~80%)가 즉시 깨진다.**
공용이면 로스터 선택에 영향을 주지 않는다.

### 저장 경계 (`D-56` 재정의)

```
저장한다   : metaCurrency, upgradeLevels        ← 정수 배열 몇 개. 직렬화가 사소하다
저장 안 한다: 런 진행 상태(시드 위치·상점 풀·배타 제거 목록·HP 누적)
```

> `D-56`은 "새로고침하면 런이 날아간다"였고 **그건 유지된다.** 메타 진행도만 살아남는다.
> 런 상태 전체를 직렬화하면 결정론 부담이 크지만, **진행도 정수 몇 개는 그렇지 않다.** 경계를 여기에 긋는다.
>
> **초기화 버튼을 둔다** — 심사자가 "강화 없는 상태"와 "강화된 상태"를 둘 다 볼 수 있어야 한다.

### 시뮬 정책 — 빌드 공간에 곱하지 않는다

메타 강화를 탐색 축에 넣으면 조합이 `6×5×5×4×3×4×3` 규모로 폭발한다.
→ **세 고정점**(`meta0` / `meta50` / `metaMax`)에서 각각 4,320 빌드를 전수 탐색한다. `D-46`(배치 제외)과 같은 논리다.

**`M1`이 단일 값이 아니라 세 값이 된다.** 목표 구간도 지점별로 다르다 (`08` §6.2).

**`provenance` 가 이 파일의 핵심이다.**

| 필드 | 없으면 |
|---|---|

**구현이 지키는 것 세 가지**

| | |
|---|---|
| `dataHash` 는 **덮어쓰기를 적용한 뒤**를 잰다 | 앞을 재면 최적화기가 돌린 **모든 실행이 같은 지문**을 갖는다 — 지문이 지문 노릇을 못 하는데 **리포트는 멀쩡해 보인다** |
| 개행을 정규화한다 | Windows 작업본과 CI 체크아웃이 CRLF/LF 로 갈리는데, 그것 때문에 지문이 달라지면 **"값이 바뀌었다" 와 구분되지 않는다** |
| `simCommit` 을 **`.git/HEAD` 를 읽어** 구한다 | `git` 을 프로세스로 부르지 않는다. `balance.yml` 가드가 *"`core`·`sim` 은 외부 프로세스를 안 띄운다"* 를 막고 있고, **리포트 한 줄 때문에 그 경계를 뚫지 않는다** |

> **밸런스 리포트는 숫자보다 출처가 중요하다.** 이 계약이 지켜지면 `balance.json` 하나로
> "이 커밋의 이 데이터로 이 시드에서 이런 결과가 나왔다"가 완결된다 — 기술 문서 4.3(검증 기준)의 재료다.

- `M2` 는 **진입 HP% 구간별 층화**라 평면 배열이 아니다 (`08` §6.2)
- `verdict` 는 `pass` / `fail`. `fail` 이면 `violations` 에 벗어난 지표 id를 담는다
- **로드 검증 대상이 아니다.** 산출물이므로 `/core` 는 이 파일을 읽지 않는다
