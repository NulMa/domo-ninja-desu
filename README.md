## 이 게임의 한 가지

**캐릭터마다 액티브 스킬이 2개인데, 하나를 사는 순간 다른 하나는 그 런 동안 영영 사라집니다.**

탱커로 설계된 캐릭터가 다른 스킬을 고르면 딜러가 됩니다. 되돌릴 수 없습니다.
고정 로스터 6명 중 3명을 데리고 8라운드를 돕니다.

이 규칙은 재미 때문만이 아니라 **검증을 위해** 골랐습니다.
선택지가 배타적이라 빌드 공간이 유한해집니다 — 정확히 **4,320가지**.

```
C(6,3) 출전 조합 20  ×  2³ 스킬 2택 8  ×  C(3,2)³ 보조 27  =  4,320
```

전수 탐색이 가능하다는 뜻이고, 그래서 *"이 게임에 지배적인 빌드가 몇 %인가"* 를
**추정이 아니라 정확한 값으로** 말할 수 있습니다. 밸런스 자동화 전체가 이 성질 위에 서 있습니다.

## 저장소 구조

```
core/        순수 C#. UnityEngine 을 참조하지 않는다 (noEngineReferences)
core.tests/  결정론 회귀 테스트
sim/         헤드리스 시뮬레이터. params.json → metrics.json
tune/        Python. Optuna 로 밸런스 파라미터 탐색
unity/       Unity 6000.5.4f1 / URP. 화면과 입력만 담당
data/        게임 데이터 JSON 5종 + 스키마 계약
docs/        기획·설계·결정 기록
```

**`core` 가 Unity 를 참조하지 못하게 막은 것이 이 저장소의 중심 제약입니다.**

밸런스 검증은 *"시뮬레이터가 낸 결과 == 실제 게임 결과"* 라는 전제 위에 있습니다.
전투 로직이 엔진에 묶이면 그 전제를 확인할 방법이 없어집니다.
그래서 `core` 는 Unity·시뮬·최적화 루프 **세 곳이 같은 어셈블리를 공유**하고,
경계는 이벤트 로그 하나입니다 — `core` 는 계산해서 로그만 뱉고, Unity 는 그 로그를 재생만 합니다.

지키자고 적어두는 대신 **컴파일러가 강제하게** 했습니다.

| 가드 | 어디서 |
|---|---|
| `noEngineReferences: true` | Unity 쪽 — `UnityEngine` 을 아예 못 찾는다 |
| CI grep 검사 | `dotnet` 쪽 — asmdef 는 여기 관여하지 않으므로 한 겹 더 |

### 결정론

같은 시드로 두 번 돌리면 결과가 같아야 합니다. 이게 깨지면 밸런스 수치 전부가 무의미해집니다.

- 정수 좌표 · **정수 제곱거리** (`sqrt` 미사용)
- **`System.Random` 금지** — 런타임 버전에 따라 구현이 바뀐 전례가 있어 알고리즘을 저장소 안에 고정 (xoshiro256\*\*)
- 용도별 난수 스트림 분리 — 전투에서 난수 소비가 한 번만 달라져도 이후 상점 결과가 통째로 밀린다
- 리스트 순회 순서에 의존하는 동률 처리 금지

## 실행 방법

### 테스트 · 시뮬레이터

```bash
dotnet test DomoNinja.sln          # 결정론 회귀 테스트
dotnet build DomoNinja.sln -c Release
dotnet artifacts/bin/DomoNinja.Sim/release/DomoNinja.Sim.dll --selftest
```

### 밸런스 탐색 루프

```bash
cd tune
py -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt   # 정확한 재현은 requirements.lock
```

### Unity

`unity/` 를 Unity **6000.5.4f1** 로 엽니다. `core` 는 로컬 UPM 패키지(`file:../../core`)로 참조됩니다.

### 커밋 로그 읽는 법

커밋 제목 맨 앞의 태그로 **AI 생성분과 사람 판단분이 갈립니다.**

```
[AI]   AI 가 생성하고 사람은 승인만 한 것
[H]    사람이 직접 썼거나 AI 산출물을 고친 것
[BAL]  시뮬레이터 리포트에 근거한 밸런스 데이터 패치
[REV]  되돌림
```

```bash
git log --oneline                    # AI/사람 경계가 한눈에
git log --grep="\[BAL\]"             # 밸런스 이터레이션 전체
```

본문에는 **`의도:`** 가 반드시 들어갑니다 — 무엇을 바꿨는지가 아니라 **왜 그렇게 지시했는지**입니다.
`[AI]`·`[BAL]` 커밋에는 `검증:` 도 필수이고, 이 규칙은 CI 가 강제합니다.

> `Co-Authored-By: Claude` 는 **팀원이 아니라 도구 표기**입니다. 팀 구성은 2인입니다.
